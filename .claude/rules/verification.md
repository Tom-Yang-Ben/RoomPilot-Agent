# 驗證規則:宣稱完成前必須有證據

**目的**:杜絕「missing_model_count=0 式」的無證據完成宣稱(見 `docs/ai-harness/FAILURE_LOG.md` #1、#4、#6)。

**觸發條件**:任何時候你要說「完成/已修好/已補齊/可以用了」,或要把任務狀態標為 done。

**具體行為**:
1. 宣稱前逐條對照本 session 的工具結果,證據四選一以上:測試輸出(貼數字,如 `68 passed`)、實跑輸出(指令+終端輸出)、檔案回讀(寫入後讀回關鍵段)、API 實測(curl 指令+回應摘要)。
2. 按 `docs/ai-harness/DEFINITION_OF_DONE.md` 對應層跑該層驗證指令與門檻;動了 floorplan 偵測邏輯就必須貼 eval 數字,動了路由就必須貼 curl。
3. 前端/互動類:證據=瀏覽器實際操作結果(截圖或逐狀態描述),後端測試通過不算前端證據。
4. 無法驗證時,只能寫「**已修改,尚未驗證**」並說明缺什麼才能驗。
5. 回報格式:結論先行 → 修改檔案清單 → 證據 → 未驗證項明列。

**禁止行為**:
- 用「應該可以了」「理論上沒問題」「測試大概會過」結案。
- 只驗檔案存在或程式啟動就宣稱功能完成(檔案存在≠完成、啟動≠正確)。
- 把「索引/文件有記錄」當「實物存在」的證據(FAILURE_LOG #4、#5)。
- 測試失敗時隱去輸出或只報通過的部分。

**驗收證據(這條規則本身怎麼驗)**:任一「完成」宣稱的訊息裡,能指出上述四類證據至少一項;抽查對話紀錄,無證據宣稱=違規。
