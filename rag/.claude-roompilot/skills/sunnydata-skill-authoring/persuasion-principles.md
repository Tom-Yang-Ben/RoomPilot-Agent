# Skill 設計的說服原則

## 總覽

LLM 對說服原則的反應與人類相同。理解這套心理學能幫你設計更有效的 skill——不是為了操弄，
而是為了確保關鍵實務在壓力下仍被遵守。

**研究基礎：** Meincke 等人（2025）以 N=28,000 次 AI 對話測試 7 種說服原則。
說服技巧讓遵守率翻倍以上（33% → 72%，p < .001）。

## 七項原則

### 1. 權威（Authority）
**是什麼：** 對專業、資格或官方來源的服從。

**在 skill 裡怎麼運作：**
- 祈使語氣：「你必須」「絕不」「永遠」
- 不可協商的框架：「沒有例外」
- 消除決策疲勞與合理化空間

**何時使用：**
- 強制紀律的 skill（TDD、交付前驗證）
- 安全關鍵實務（金鑰不得回顯、不得提交 `.anthropic_key`）
- 已確立的最佳實踐

**範例：**
```markdown
✅ 先寫程式碼再寫測試？刪掉。重來。沒有例外。
❌ 可行的話考慮先寫測試。
```

### 2. 承諾（Commitment）
**是什麼：** 與先前的行動、陳述或公開宣告保持一致。

**在 skill 裡怎麼運作：**
- 要求宣告：「宣告你正在使用哪個 skill」
- 強迫明確選擇：「選 A、B 或 C」
- 使用追蹤：用 TodoWrite 管理檢查清單

**何時使用：**
- 確保 skill 真的被執行
- 多步驟流程（如八段式 Advanced RAG 改動）
- 問責機制

**範例：**
```markdown
✅ 找到 skill 時，你必須宣告：「我正在使用 [Skill 名稱]」
❌ 可以考慮讓夥伴知道你用了哪個 skill。
```

### 3. 稀缺（Scarcity）
**是什麼：** 來自時間限制或有限可得性的急迫感。

**在 skill 裡怎麼運作：**
- 有時限的要求：「在繼續之前」
- 順序相依：「在 X 之後立刻」
- 防止拖延

**何時使用：**
- 需要立即驗證的要求（例如批次跑完立刻對帳，避免額度白燒）
- 有時效的工作流
- 防止「我之後再做」

**範例：**
```markdown
✅ 任務完成後，立刻在繼續之前發起程式碼審查。
❌ 你方便的時候再審查程式碼。
```

### 4. 社會認同（Social Proof）
**是什麼：** 服從別人的做法或被視為常態的做法。

**在 skill 裡怎麼運作：**
- 普遍模式：「每一次」「永遠」
- 失敗模式：「沒有 Y 的 X = 失敗」
- 建立規範

**何時使用：**
- 記錄普遍實務
- 警告常見失敗（例如「`rag_indexable` 寫進 Chroma `where` = 命中 0 筆。每一次。」）
- 強化標準

**範例：**
```markdown
✅ 沒有 TodoWrite 追蹤的檢查清單 = 步驟會被跳過。每一次。
❌ 有些人覺得 TodoWrite 對檢查清單很有幫助。
```

### 5. 同一性（Unity）
**是什麼：** 共享身分、「我們感」、內群體歸屬。

**在 skill 裡怎麼運作：**
- 協作語言：「我們的程式庫」「我們是同事」
- 共同目標：「我們都想要品質」

**何時使用：**
- 協作型工作流
- 建立團隊文化
- 非階層式實務

**範例：**
```markdown
✅ 我們是一起工作的同事。我需要你誠實的技術判斷。
❌ 如果我錯了你大概可以跟我說。
```

### 6. 互惠（Reciprocity）
**是什麼：** 回報所受益處的義務感。

**怎麼運作：**
- 少用 — 容易顯得操弄
- 在 skill 中很少需要

**何時避免：**
- 幾乎總是（其他原則更有效）

### 7. 喜好（Liking）
**是什麼：** 偏好與自己喜歡的人合作。

**怎麼運作：**
- **不要用於強制遵守**
- 與誠實回饋的文化衝突
- 造成阿諛奉承

**何時避免：**
- 紀律強制場合一律避免

## 依 Skill 類型組合原則

| Skill 類型 | 使用 | 避免 |
|------------|-----|-------|
| 紀律強制型 | 權威 + 承諾 + 社會認同 | 喜好、互惠 |
| 指引／技巧型 | 適度權威 + 同一性 | 過重的權威 |
| 協作型 | 同一性 + 承諾 | 權威、喜好 |
| 參考型 | 只求清楚 | 所有說服技巧 |

## 為什麼有效：心理學

**明確界線的規則減少合理化：**
- 「你必須」消除決策疲勞
- 絕對語氣消滅「這算不算例外？」的疑問
- 明確的反合理化條款堵住特定漏洞

**執行意圖產生自動行為：**
- 清楚的觸發點 + 必要動作 = 自動執行
- 「當 X 時，做 Y」比「一般來說做 Y」更有效
- 降低遵守所需的認知負荷

**LLM 是類人（parahuman）：**
- 訓練在包含這些模式的人類文本上
- 訓練資料中權威語言之後常接著服從
- 承諾序列（陳述 → 行動）被大量示範
- 社會認同模式（大家都這麼做）建立規範

## 合乎倫理的使用

**正當：**
- 確保關鍵實務被遵守
- 建立有效的文件
- 預防可預見的失敗

**不正當：**
- 為私利操弄
- 製造假的急迫感
- 以罪惡感逼迫遵守

**判準：** 如果對方完全理解這個技巧，它仍然符合使用者的真實利益嗎？

## 研究引用

**Cialdini, R. B. (2021).** *Influence: The Psychology of Persuasion (New and Expanded).* Harper Business.
- 七項說服原則
- 影響力研究的實證基礎

**Meincke, L., Shapiro, D., Duckworth, A. L., Mollick, E., Mollick, L., & Cialdini, R. (2025).** Call Me A Jerk: Persuading AI to Comply with Objectionable Requests. University of Pennsylvania.
- 以 N=28,000 次 LLM 對話測試 7 項原則
- 使用說服技巧後遵守率由 33% 提升至 72%
- 權威、承諾、稀缺最有效
- 驗證 LLM 行為的類人模型

## 速查

設計 skill 時問自己：

1. **這是哪一型？**（紀律 vs 指引 vs 參考）
2. **我想改變什麼行為？**
3. **適用哪些原則？**（紀律型通常是權威 + 承諾）
4. **我是不是混用太多？**（不要七項全上）
5. **這合乎倫理嗎？**（是否符合使用者的真實利益？）
