## 問題 1：躺椅擋在沙發前、茶几/電視櫃序列不成立

### 根因（三個互相疊加）

1. **躺椅先於副件擺放**：`placement_hints` 只有主件(0)/泛用(1)/副件(2)
   三級，lounge-chair 屬泛用件且面積大 → 先於茶几/電視櫃擺放；它沒有
   類型候選表，泛用候選就是**房間中央** —— 正是沙發正前方的成組位。
2. **電視櫃「對面牆」成組候選只有單一定點**：對面牆該點落在門淨空帶
   （北牆中段有 92cm 門的通行/開門淨空）就整組被否決，退回「長邊優先」
   靠牆掃描 → 落到任意一面長牆，與沙發呈 L 型復發。
3. **沙發自己的候選太少**：類型候選只有下牆兩點，被門淨空壓掉後直接
   進靠牆掃描（長邊優先→南牆）；南牆的對面（北牆）整段是門淨空，
   電視櫃在對面牆物理上無合法位——L 型被房型幾何鎖死。

### 修復

- **agent（本人目錄，僅列出）**：`knowledge.py` 新增
  `FREE_SEATING_FAMILIES = ("armchair", "lounge-chair")`；`place.py`
  `placement_hints` 加第 3 級「自由座椅最後擺」。不列入 COMPANION_OF
  （躺椅可獨立存在於臥室，主件缺席不應被移除）。
- `scene_service.py`（非 agent）：
  - 電視櫃對面牆成組候選由 1 點擴為沿牆 5 個側移點（0/±80/±160cm，
    正對位優先），單點被門淨空否決不再整組報廢；
  - 沙發類型候選在下牆之後補左右牆（面向室內 90/270），下牆被壓掉時
    改走側軸，讓對面仍有電視櫃的位置。

### grwsgs 客廳重放（含茶几重新選件）

```
sofa         (60.2, -264.1)  rot 90   西牆面東
coffee-table (173.5,-264.1)  rot 90   沙發正前方（同一列）
tv-bench     (361.9,-264.1)  rot 270  東牆、沙發正對面，正面連線 cos=1.00
lounge-chair (294.3,-249.0)  rot 270  退到側邊、面向茶几組
```

沙發 → 茶几 → 電視櫃 同列成序；躺椅不再佔用沙發正前方。
（注：使用者存檔中的茶几已被上一輪修復迴圈移除；重新產生配置時
choose_furniture_items 會重新選入。）

## 問題 2：每扇門上方多出一塊懸空的牆

### 根因

前一輪恢復門楣時，把門楣畫在 `door_segments` 的線段上。但**門的 2D
線段是門扇符號**：grwsgs 五扇門實測全部離最近牆線 21-23cm（平行外偏），
door-2/3 的線段甚至是**開門葉**（與實際門洞互相垂直）。門楣因此變成
懸在門邊空中的牆塊。舊 `buildConfirmedDoorLeaves` 的 header 用的是
`wall_opening_segment ‖ closed_leaf_segment`（第 4 步牆縫線段），從來
不用門段本身。

### 修復（`backend/server/static/scene_shell_geometry.js`）

- 門楣/門頂蓋改掛在 `wall_opening_segment ‖ closed_leaf_segment`
  （與舊 header 同優先序）；兩者皆無則不畫（舊缺省行為）。
- 加 `nearAnyWallLine` 防呆：`doorOpeningForWallTopology` 對缺 swing
  資料的門會合成離牆很遠的 closed leaf，門楣線段必須貼近某條牆線
  （容差 2×牆厚、允許延伸縫寬）否則不畫——畫錯位置就是懸空牆塊。
- grwsgs 重放：5 個門楣全部與牆共線落在縫內（縫中點到兩側斷開牆段
  端點的距離 = 半跨距，例 door-2：47.0 = 94/2 精確吻合）。
