# 2026-08-02 逐房問卷兩處死結（修改到他人程式碼的紀錄）

> 本檔記錄「修改到非本人負責模組」的內容，供該模組 owner 覆核。
> 受影響模組：`backend/server/static/scene_v2.js`（第 5 步逐房問卷，owner 見 `docs/TEAM_AI_OWNERSHIP.md`）。
> 發現方式：以 `data/testdata/png/floor04.png` 實跑八步流程，卡在第 5 步無法進入第 6 步。

## 影響

第 5 步「逐房問卷」**任何一間房都無法確認**，因此第 6 步（配置與預覽）整段進不去。
兩個 bug 各自獨立，但都在同一支檔案，且都會讓使用者以為是自己操作錯誤 —— 畫面沒有任何有效錯誤訊息。

## Bug 1：材質閘門死結，房間永遠確認不了

### 問題

`scene_v2.js` 的 `confirmQuestionnaireFinishes()` 用 `finishesGate(draft).ready` 當作前置條件：

```js
const finishGate = finishesGate(draft);
if (!finishGate.ready) { …顯示錯誤; return; }        // ← 擋在這裡
…
Object.assign(draft, { …draft, confirmed: true, … }); // ← confirmed 在閘門之後才寫入
```

而 `scene_questionnaire_test2.js:189` 的 `finishesGate()`：

```js
ready: missing.length === 0 && finishes.confirmed === true
```

**`ready` 要求 `confirmed === true`，但 `confirmed` 只有在通過閘門之後才會被設。**
八項材質全部選完仍過不了關，且錯誤訊息會顯示成「請完成本房材質：」後面空白 ——
因為 `missing` 真的是空陣列，卡住的是 `confirmed` 那一項。

### 修復

**只改呼叫端，`finishesGate()` 本身不動。**
`finishesGate` 還有第二個呼叫端（`scene_v2.js` 最終送出處），那裡「所有房都必須已 confirmed」
是正確語意，需要完整的 `ready`。所以只把逐房確認那一處改成看 `missing`：

```js
const finishGate = finishesGate(draft);
if (finishGate.missing.length) { …顯示錯誤; return; }
```

語意：`confirmed` 是這個動作的**結果**，不是它的**前提**。

### 檔案

- `backend/server/static/scene_v2.js` — `confirmQuestionnaireFinishes()` 內一處判斷式（＋說明註解）
- `backend/server/static/scene_questionnaire_test2.js` — **未修改**

## Bug 2：家具勾選與數量調整完全不生效

### 問題

`roomFurnitureRequirement()` **每次呼叫都重建 `requirement.furniture` 物件**：

```js
requirement.furniture = {
  required: [], optional: [], selected: [], deferred: [],
  ...(requirement.furniture || {}),
};
return requirement.furniture;          // ← 每次都是一個新物件
```

呼叫端拿到的參考會在下一次呼叫後失效。以 `updateQuestionnaireFurnitureSelection()` 為例：

1. `const furniture = roomFurnitureRequirement(room.id)` → 取得物件 **A**，state 指向 A
2. `questionnaireFurnitureOffers(room)`（查 offer 用）內部**又呼叫了一次** `roomFurnitureRequirement`
   → 建立物件 **B**，state 改指向 B
3. 之後所有 `furniture.selected = …`、`furniture.required = …` 全部寫進 **A**，
   但 state 已經是 **B** → 使用者的修改完全遺失

同一個模式在三個函式中都成立：
`updateQuestionnaireFurnitureSelection`、`updateQuestionnaireFurnitureQuantity`、
`updateQuestionnaireFurnitureVariant`。

症狀：勾選框點了立刻彈回、數量加減按鈕沒反應、換款下拉沒作用。
伺服器預設帶入的家具（床、衣櫃）不受影響，因為它們本來就在 state 裡，
所以外觀上像是「只有部分家具壞掉」，更難察覺。

### 修復

`roomFurnitureRequirement()` 改為**就地補齊預設值並回傳同一個參考**，不再重建物件：

```js
if (!requirement.furniture) requirement.furniture = {};
const furniture = requirement.furniture;
if (!Array.isArray(furniture.required)) furniture.required = [];
… // optional / selected / deferred 同
return furniture;
```

三個呼叫端**都不必改**，因為它們原本的寫法在參考穩定之後就是正確的。

### 檔案

- `backend/server/static/scene_v2.js` — `roomFurnitureRequirement()` 函式本體（＋說明註解）
