# 2026-08-02 家具全部擠進同一間房（修改到他人程式碼的紀錄）

> 本檔記錄「修改到非本人負責模組」的內容，供該模組 owner 覆核。
> 受影響模組：`backend/server/scene_service.py`（owner 見 `docs/TEAM_AI_OWNERSHIP.md`）。
> 回報來源：使用者提供 `feedback.png`，第 6 步 3D 畫面中所有家具集中在同一間房。
> 測資：`data/testdata/png/floor04.png`（7 房：臥室／廚房／書房儲藏室／走道／浴室／客廳／陽台）。

## 問題

第 6 步「完成需求並建立 2D+3D 配置」產生的配置，**13 件家具不分房型全部落在同一間房**。

根因在 `build_scene_payload()`：整層樓只呼叫一次 `generate_layout()`，而且

```python
place_boundary=_largest_region_boundary(parsed_floorplan, engine_room)
```

`place_boundary` 固定是**面積最大的那一間**。柵格遮罩的 `¬room_mask` 會把其餘房間
全部視為「房外」而禁放，於是每一件家具無論 `placement_room_id` 指到哪，都被擠進那一間。

floor04 實測特別明顯：廚房 18.53 m² 只比臥室 18.49 m² 大 **0.04 m²**，
於是床、衣櫃、床頭櫃、鏡櫃、植栽全部跑進廚房。

實測量化（修改前）：

```
bed             room-1 臥室   → 實際落在 room-2 廚房   ← 不一致
wardrobe        room-1 臥室   → room-2 廚房            ← 不一致
storage-cabinet room-3 書房   → room-2 廚房            ← 不一致
mirror-cabinet  room-5 浴室   → room-2 廚房            ← 不一致
lounge-chair    room-6 客廳   → room-2 廚房            ← 不一致
flower-pots     room-7 陽台   → room-2 廚房            ← 不一致
不一致 11 / 13 件
```

這與 `docs/擺位計算邏輯.md` §1.2 的管線相違 —— 規格明寫是
「**逐房** → ③禁放遮罩 blocked_masks → ④房間輪廓邊 → ⑤房型規則」。

> 這是既有設計限制，**不是**柵格引擎（commit 329ef146）造成的回歸。
> 舊的 Shapely 路徑用同一個 `boundary` 做 `_inside_boundary()`，行為相同；
> 只是換引擎後畫面上變得明顯。

## 修復

新增 `generate_layout_by_room()`，依房間分組後**每間房各自在自己的邊界內**擺位：

1. 依 `placement_room_id` / `auto_decor_room_id` 分組
2. 沒有指定房的品項改查 `backend/agent/knowledge.py` 的 `ROOM_AFFINITY`
   （sofa／coffee-table／tv-bench → `living_room`；bed／bedside-table → `bedroom`…），
   找房型相符的房間；同房型有多間時取面積最大者，結果具決定性
3. 兩者都查不到才退回 `_largest_region_boundary()`（維持原行為）
4. 每組用 `_region_boundary_by_id()` 取自己的邊界，各自呼叫 `generate_layout()`
5. 由適配表決定的房間**寫回 `placement_room_id`**，否則前端會照空欄位把它們歸進
   「未指定空間」，與實際落點不符
6. 回傳順序與輸入相同，payload 契約不變

`generate_layout()` 本身**沒有修改**。`preserve_existing_count` 的「前 N 筆」語意
在分組後換算成各組的前 N 筆（分組保持相對順序，所以成立）。

`build_scene_payload()` 內兩個呼叫點（初次配置、`replace_and_place` 修復重擺）
都改為呼叫新函式。
