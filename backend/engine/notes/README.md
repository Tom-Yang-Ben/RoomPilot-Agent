## 為什麼不再寫日記

2026-08-01 之前是每日一檔，累積到五份、2284 行，彼此互相推翻又互相引用。
接手要同時讀五份還得自己判斷哪一節過期，實際造成過兩次誤判；更嚴重的是
**擱置最久的待辦沒有任何地方看得出來**——7/29 就決定的「門窗進 Room」
在三天內沒有任何一份日記提醒它還沒做。

改成依主題組織後，「還沒做什麼」與「哪裡打架」各自有固定位置，不會被新的
一天沖掉。**請不要再新增日期檔**，有新結論就更新這兩本。

原始五份日記已刪除，內容全數併入。需要原始脈絡時查 git 歷史：

```bash
git log --oneline --diff-filter=D -- 'backend/engine/notes/*2026-0*'
git show <commit>:backend/engine/notes/<檔名>
```

## 維護規則

1. 拍板結果要寫進 `room_strategy/README.md` 或引擎 README，不要只留在筆記。
2. 完成一項就把總帳 §2 的對應列改掉，並在 §1 補一行「做了什麼／怎麼驗證」。
3. 新結論推翻舊結論時，在總帳 §6.5 記一行「哪個結論作廢」。
4. 不得把「規格寫了」說成「引擎做完」，也不得把「引擎測過」說成「第 6 步已啟用」。
