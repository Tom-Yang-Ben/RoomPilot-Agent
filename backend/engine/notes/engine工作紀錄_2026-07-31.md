### 踩過的坑

1. **`!` 開頭的指令貼進終端機會失效**。`!` 是 Claude Code 輸入框語法；在 bash 裡是「反轉結果」運算子，會讓 `!cmd && next` 的 next 永遠不執行。長指令一律寫成腳本再 `sudo bash`。
2. `main.py` 的 `_furniture_payload_cache()` 有 `@lru_cache`。**改 DB 或 `.env` 後第 6 步家具要重啟 server 才生效**；RAG 走連線池，不用重啟。

### 五個關鍵決定與理由

- **A. 房間標籤只當「優先加分」，不當「硬過濾」**（最重要）。catalog 的 `room_codes` 覆蓋不全：儲藏室 0 件、玄關無鞋櫃、多功能室無此碼。硬過濾會回傳零件。**真正決定候選的是類型白名單。**這一條同時解掉儲藏室、玄關、多功能室三個死局。
- **B. 主臥／次臥共用骨架，只差量與可選**。主臥雙人床兩側各一床頭櫃；次臥給 2 個會先擠爆小房。次臥額外開放「書桌＋辦公椅成組」為可選（台灣次臥最常見的第二用途）。**次臥若問卷標為兒童房，額外開放 `kids_room`(779) 候選池**，不新開房型——兒童房骨架與次臥完全相同。
- **C. 廚房／浴室／陽台／走道四間維持空白**。資料說話：廚房無可自動擺的主家具、浴室只有鏡子與鏡櫃、陽台無戶外桌椅、走道留空即功能。**寧空勿塞**——留白使用者知道待補，塞錯會讓人不信任整套自動配置。
- **D. 儲藏室走純類型白名單**。`shelving-unit`(80)、`storage-furniture`(20)、`storage-solution-system`(59)、`cabinet-cupboard`(146) 都存在，只是被標到 study／bedroom／living_room。決定 A 的直接應用。
- **E. 多功能室路由到既有骨架**：客房→次臥、工作→書房、起居延伸→客廳、未填→只放收納或留空。多功能室的本質是「還沒決定用途的房間」，替它發明第四套骨架只會產生孤兒規則。

### 5.2 接縫已經留好

`/api/agent/furniture/select` 的 `offers` 是 **payload 欄位**，後端照單全收，誰產不管。`room_strategy/README.md` 第 134 行早就寫了「RAG：依最少槽位產 `offers`」標記未接。

RAG 回傳結構與 offers **幾乎同構**：

```
一次查詢 → blocks[N]（每個 block = 一個槽位）
         → 每 block hits[8]
         → hit.furniture 含 item_id, normalized_type, width_cm/depth_cm/height_cm,

```

**一次呼叫回一整間房的所有槽位**，正是 `offers[room_id]` 要的形狀；欄位名（`normalized_type`／`model_url`／`has_model`）也對得上。

### 5.3 可行性（以定版資料庫評估）

- **資產：零缺口。** 7,958 件**全部**有 GLB ＋ front/side/angle-45 三視角圖。
- **候選數：夠，唯一警訊是玄關。**
  ```
  desk 527 | sofa 490 | dining-chair 411 | office-chair 175 | dining-table 133
  bed 110 | shelving-unit 80 | wardrobe 72 | pax-wardrobe 72 | tv-bench 56
  bedside-table 54 | storage-furniture 20 | shoe-cabinet 5  ← 警訊
  ```
- **效能：唯一真正的障礙。** 單次查詢（模型已熱）**47.8 秒**：
  ```
  parse (LLM)            8.8s
  retrieve_and_rerank   38.5s   ← 瓶頸（bge-reranker-v2-m3 cross-encoder 跑 CPU）
  hydrate                0.01s
  ```
  四房透天 ≈ 3 分鐘以上，互動流程不可接受。

- **但瓶頸有解：GPU 有卻沒開。**
  ```
  torch.cuda.is_available() = True — NVIDIA RTX 2060 6GB
  .env: ROOMPILOT_RAG_DEVICE=cpu   ← 寫死跑 CPU
  ```
  ⚠️ 風險：BGE-M3 ＋ reranker 兩個模型同時上 6GB VRAM 可能 OOM，必要時只把 reranker 上 GPU，或改 fp16。
