1 · 一句話結論

兩邊差在一次完整的「外殼幾何管線重寫」(規格 docs/superpowers/specs/2026-08-02-scene-shell-rebuild-design.md),不是排版、也不是小重構。
bella-new = merge-base 的舊內聯管線原封不動(她 7 個 commit 只碰第 5–8 步,沒動 shell);
本分支 = 重建後的純函式管線:幾何全在可 node 單測的 scene_shell_geometry.js,viewer 只做「描述 → mesh」。
→ 因此「換成 bella-new 邏輯」= 回退整個 shell 重建,會連帶影響 panorama 副程式、4 個測試檔、cache-key 雜湊鏈,並重新引入 3 份 fix 紀錄修掉的使用者回報 bug。

2 · 相同的部分(同源 scaffold)

兩邊 createRoom(sceneData) 讀完全相同的輸入—— sceneData.floorplan 的 width_cm / depth_cm / room_height_cm / wall_segments / window_segments / door_segments / source (本分支另讀 wall_polys)——外層編排也幾乎逐行相同:

  • 地板材質、presentation ground、陰影相機參數
  • 三分支牆決策:wall-mass(多房 DXF 無線段) / 線段牆(≥2 段) / fallback 盒房
  • 門診斷 roompilotDoorDiagnostics、createRoomSurfaceOverrides(逐房材質)、天花、buildStructuralMembers、buildCirculationRoute、buildFloorPlanOverlay、createStyleLights

差別全部集中在中間那一段:牆/門窗/地板的幾何是「怎麼算出來的」。

3 · 核心差異:幾何怎麼從平面圖算出來

面向bella-new(內聯命令式)本分支(純函式層)
幾何運算位置 邊算幾何邊建 mesh,geometry 與 rendering 交織在 createRoom 與各 build* 內 抽成 buildSceneModel(plan,cfg)(scene_shell_geometry.js,不 import three、可 node 單測);先輸出 {boxes, polygonWalls, floor, cameraPose, bbox, openings} 描述,viewer 只做描述→mesh
常數 散落魔數:wallThickness=12、room_height_cm||270、ground y=-3.2 全集中在凍結的 DEFAULT_SCENE_CONFIG + shellConfig() 覆蓋(牆高 min 210、sill/head、epsilon、cluster 距離/角度、floorMargin…)
開口去重 dedupeArchitecturalOpeningsFor3d(...) 分別套門/窗 clusterOpeningSegments(...):文件化的 Union-Find 群聚,含明文 ID 保護(兩開口 ID 皆非空且不同 → 永不合併)、<minWindowWidth 丟棄但鎖定開口豁免
路徑 A(線段牆) buildSegmentWalls(...) + buildConfirmedDoorLeaves(...)(各自建 mesh 兼算幾何) 純函式 segmentWallBoxes + junctionFillBoxes + 縫內開口 gapTopCap,由 buildShellBoxes 吃 boxes 出 mesh

4 · 不只是重構——實際幾何行為變更

① 地板 平面 → 厚盒

基底樓板由旋轉平面改成 5cm 實心盒,ground 下移到 -6.2 避免側面交疊。是可見的視覺變更。

② 相機自適應

不再寫死;fitCameraPose(bbox) 依各檔尺度推算,大小案子取景一致。

③ 開口群聚換演算法

dedupe → 文件化 Union-Find + ID 保護,DXF 多平行線去重更穩、確認門窗身份不被吃掉。

④ 兩個新防呆

門楣 nearAnyWallLine 貼牆守衛 + 縫內開口 gapTopCap 補頂線;bella-new 皆無。

7 · 兩種切換情境與建議

(a) 外科式:只回退 shell 幾何

保留家具/材質/panorama,只把 createRoom + 外殼換 bella 內聯版。
實際不可行:shellModel 是多處共用資料結構、panorama 依賴 scene_builders、6-5 相機依賴 cameraPose——牽一髮動全身,且回歸 3 份 fix。

(b) 整包:採 bella-new viewer

連同她的家具/材質/編號一起換。
等於丟掉本分支全部 3D 演進(shell 重建 + loadScene 生命週期 + step6 逐房材質/預覽/編號),並回退所有已修 bug。
建議:不要「換成 bella-new 邏輯」。若目的是取得 bella-new 的某項功能(逐房材質即時預覽、單房 3D 預覽、家具編號),正確做法是在本分支的 buildSceneModel 描述層 + 增量 viewer API 上重作那一項,而非替換管線。這也是 bella-new-step5-8-frontend-mapping.md §5.2「viewer 架構分歧,只能重作不能複製」的幾何實證。
