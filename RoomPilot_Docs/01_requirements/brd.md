## 3. 未來流程 (To-Be)

RoomPilot 的八步流程（`README.md:139-152`；事實檔 01-product §2）：

```mermaid
flowchart LR
    S1[1 建立專案] --> S2[2 上傳平面圖並自動辨識]
    S2 --> S3[3 兩點標定確認實際尺寸]
    S3 --> S4[4 人工校正結構並確認]
    S4 --> S5[5 逐房需求問卷與風格色卡]
    S5 --> S6[6 自動產生 A/B 配置並 2D/3D 編輯]
    S6 --> S7[7 鎖定方案與各房視角]
    S7 --> S8[8 AI 寫實生圖與交付成果包]
```

- 與 As-Is 的關鍵差異：
  - 平面圖辨識與尺寸換算自動化，人只做校正與確認（REQ-002、REQ-003、REQ-004）。
  - 家具擺放的合法性（碰撞、走道、開門淨空）由系統即時把關，取代肉眼經驗檢查（REQ-007）。
  - 需求、風格、配置、寫實圖、提案 PDF、工程報告與估價在同一條流程內產出（REQ-005、REQ-011、REQ-012）。
  - 專案可中斷後恢復，多人／多分頁同時編輯不互相覆寫（REQ-001）。
- 過渡期並行策略：待確認（見 §5）。

## 4. 業務規則 (Business Rules)

BR 為本文件起源的業務規則 ID，下游 SRS／測試引用不重述；每條的系統面依據沿用登錄簿 [`../00-registry.md`](../00-registry.md) 的穩定 ID。

| ID | 規則 | 例外情境 | 來源 |
| :--- | :--- | :--- | :--- |
| BR-001 | 空間結構（牆／門／窗）一經第 4 步確認即鎖定；要改結構必須回到第 4 步，且已擺的家具要重新檢查 | 無 | REQ-004、ACPT-004；`README.md:154-155` |
| BR-002 | 家具擺放是否合法（撞到東西、擋走道、擋門）由系統單一裁決；有未解決的問題就不能進下一步 | 無 | REQ-007、ADR-002；`README.md:154-155` |
| BR-003 | 方案中的家具只能來自已驗證的官方家具目錄（8,675 件）；未驗證、隔離中的品項不得出現在方案 | 無 | REQ-013、NFR-005 |
| BR-004 | 家電（冰箱、洗衣機等）只作為需求記錄並影響最後的寫實圖，不出現在 2D/3D 擺設 | 無 | REQ-014、ADR-004；`AGENTS.md:56` |
| BR-005 | 色卡比較圖每個專案只能成功產生一次；寫實圖每個房間只有一次改圖額度 | 無 | REQ-010、REQ-011、ACPT-009、ACPT-010 |
| BR-006 | 同一專案被多個視窗同時編輯時，較晚儲存且版本落後的一方不得覆寫他人變更，需先重新載入 | 無 | ACPT-014、NFR-002 |
| BR-007 | 所有空間與家具尺寸一律以公分溝通與記錄 | 無 | NFR-001、ACPT-003；`AGENTS.md:50-51` |
| BR-008 | 交付文件必須完整才交付：產出環境不齊備時明確告知失敗，不交付殘缺的提案 PDF | 無 | ACPT-011；`README.md:111-117` |
