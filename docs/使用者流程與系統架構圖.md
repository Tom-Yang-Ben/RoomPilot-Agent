# RoomPilot 使用者流程與系統架構圖

最後更新：2026-07-29  
適用分支：`bella-test1`

本文件以目前正式網頁 `backend/server/static/scene.html`、`scene_v2.js`、FastAPI 與既有跨模組契約為準。圖中的「目前」表示已接入 Bella 流程；「部署擴充」表示可採用、但尚未拆成正式背景 worker 的架構。

## 1. 使用者八步流程

```mermaid
flowchart TD
    A["1 建立專案\n名稱與備註"] --> B["2 上傳平面圖\nPNG / JPG / DXF"]
    B --> C["3 確定尺寸\n兩點標定與公分尺度"]
    C --> D["4 空間與結構\n確認房間、牆、門、窗、樑、柱"]
    D --> E["5 需求問卷\n全屋風格、材質與冷氣範圍"]
    E --> F["5 逐房用途與家具\n類型、尺寸、數量與家具偏好"]
    F --> G["5 方案摘要\n確認後建立方案 A、B"]
    G --> H["6 2D + 3D 配置\n同畫面檢查、拖曳、替換與材質調整"]
    H --> I["7 方案鎖定與視角\n逐房選視角、微調、保存"]
    I --> J["8 AI 渲染與成果包\n依房間輸出渲染任務與結果"]

    C -. "尺度不正確" .-> C
    D -. "結構需修改" .-> D
    H -. "大幅改牆、門、窗、樑、柱" .-> D
    H -. "家具碰撞／淨空不足" .-> H
    I -. "想改家具或材質" .-> H
```

### 第 5 步精簡問卷

```mermaid
flowchart LR
    A["全屋風格卡\n再選牆、地、天花材質"] --> B["冷氣形式與套用範圍\n預設客廳、臥室、書房"]
    B --> C["選取房間\n平面圖或房間清單"]
    C --> D["勾選用途與家具\n類型、尺寸、數量、家具偏好"]
    D --> E{"所有房間已確認？"}
    E -- "否" --> C
    E -- "是" --> F["方案摘要"]
    F --> G["建立方案 A、B\n2D + 3D"]

    D -. "尺寸風險或缺 GLB" .-> X["記錄需求，繼續下一房\n第 6 步列入待處理"]
```

使用者在第 5 步不需要再回答「整面衣櫃或更衣區」、「電視或閱讀角」等強制極與極題目。舊視覺題庫仍可供 RAG 作關係與偏好證據，但不會阻擋問卷完成。

2026-08-02 補充：「全屋風格與設備」新增「生圖細節（可留白）」六題——間接光、天花分區、送風方式、維修口、吊扇、廚房家電外露。這不是把極與極問卷收回來：逐房視覺題庫維持停用（`state.visualQuestions` 仍為空），這六題只問一次、可全部留白，而且只進第 8 步生圖 prompt，不碰選件也不碰擺放參數。理由是這六個軸在 3D 場景裡沒有對應物件，模型本來就得自行補完；不問的話等於讓 AI 亂猜天花與設備。界線由 `docs/contracts/REMOTE_RENDER_CONTRACT.md` 與 `tests/test_questionnaire_visual_catalog.py` 的守門測試維持。

### 第 6 步家具操作

```mermaid
flowchart TD
    A["進入方案 A 或 B"] --> B["3D 主畫面\n預設自由旋轉"]
    B --> C["點選家具或 2D 編號\n3D 顯示藍色選取框"]
    C --> D{"使用者操作"}
    D --> E["定位\n保持視角，只顯示家具位置"]
    D --> F["更換家具\n推薦 + 資料庫篩選／搜尋"]
    D --> G["刪除家具"]
    D --> H["拖曳／旋轉\n靠牆磁吸、碰撞與淨空檢查"]
    F --> I["保留相機狀態\n重載場景後回到編輯模式"]
    G --> I
    H --> J{"合法？"}
    J -- "是" --> K["同步 2D、3D、專案保存"]
    J -- "否" --> L["待處理清單\n定位、替換、刪除或重新配置"]
    L --> D
```

## 2. 現行系統架構

```mermaid
flowchart TB
    User["使用者瀏覽器\nHTML / CSS / JavaScript / Three.js"]
    UI["Bella 正式 UI\nbackend/server/static\n八步流程、2D+3D、專案恢復"]
    API["Bella FastAPI\nbackend/server/main.py\n專案、檔案、流程、場景 API"]
    Store["目前專案持久化\nFastAPI project/workflow state"]

    Vision["Cody 平面圖辨識\nbackend/floorplan\nPNG/JPG/DXF -> layout_json"]
    Spatial["Django 空間資料\nbackend/spatial_data\n尺寸、相鄰、evaluation"]
    Agent["Yen 需求與選件\nbackend/agent\n需求結構化、候選與說明"]
    Catalog["Kai catalog\nPostgreSQL 優先\nJSON 備援、CloudFront GLB/PNG"]
    Engine["Ancai 配置引擎\nbackend/engine\n擺放、碰撞、淨空、合法性"]
    Upgrade["Cody 3D 格局轉換\nbackend/upgrade3d\n牆、地板、門窗幾何"]
    Render["AI 渲染服務\n第 8 步逐房任務"]

    User <--> UI
    UI <--> API
    API <--> Store
    API --> Vision
    Vision --> Spatial
    Spatial --> API
    API --> Agent
    Agent <--> Catalog
    Agent --> Engine
    API --> Engine
    API --> Upgrade
    Engine --> API
    Upgrade --> API
    API --> Render
    Render --> API
```

## 3. 主要資料生命週期

```mermaid
sequenceDiagram
    participant U as 使用者
    participant B as Bella UI / FastAPI
    participant C as Cody / Django
    participant K as Kai catalog / RAG
    participant Y as Yen agent
    participant A as Ancai engine

    U->>B: 上傳平面圖並標定尺度
    B->>C: 辨識與空間關係處理
    C-->>B: layout_json 草稿
    U->>B: 確認房間與結構
    B->>B: 保存確認版 layout_json
    U->>B: 先選全屋風格、材質與冷氣範圍，再逐房選用途與家具
    B->>K: 查詢家具、材質、風格關係與資產
    K-->>B: 有證據的候選資料
    B->>Y: 結構化需求與候選選件
    Y-->>B: 家具候選與說明
    B->>A: layout_json + 候選家具 + 限制
    A-->>B: 合法座標、衝突／淨空報告
    B-->>U: scene_json、方案 A/B、2D+3D 編輯
```

### 資料責任

| 資料 | 生產者 | 用途 | 不能承擔的責任 |
|---|---|---|---|
| `layout_json` | Cody 辨識，使用者於第 4 步確認 | 空間、牆、門、窗、房間、尺度 | 家具、材質、視角、設計決策 |
| RAG 關係證據 | Kai catalog + Django spatial metadata | 推薦家具、風格、材質與限制關聯 | 座標、碰撞、淨空、結構合法性 |
| `scene_json` | Yen 候選 + Ancai 幾何 + Bella service | 家具、材質、燈光、配置與方案 | 取代 layout 的建築辨識結果 |
| 2D/3D 編輯狀態 | Bella UI | 使用者調整、方案 A/B、視角與保存 | 判定幾何是否合法 |
| 合法性報告 | Ancai engine | 碰撞、淨空、門窗、邊界與朝向 | 選擇使用者風格或資料庫資料 |

## 4. Catalog、RAG 與幾何配置的分工

```mermaid
flowchart LR
    Q["使用者輸入\n房間、家具、文字描述、風格與材質"] --> R["關係檢索 / RAG\n找候選與理由"]
    DB["Kai PostgreSQL / JSON\n家具、GLB、PNG、尺寸、標籤"] --> R
    R --> S["候選家具與材質"]
    L["確認版 layout_json\n房間邊界、牆、門、窗"] --> G["Ancai 幾何規則"]
    S --> G
    G --> V["合法 scene_json\n位置、旋轉、淨空、問題清單"]
    V --> UI["Bella 2D+3D UI"]

    R -. "不決定精確座標" .-> G
    G -. "不自行改寫使用者風格" .-> R
```

## 5. 部署擴充架構

目前 demo 以 FastAPI 同步流程為主。專案正式部署或耗時工作增加後，可改成下列非同步架構；這不是目前網頁必須依賴的條件。

```mermaid
flowchart LR
    API["FastAPI Web/API"] --> Q1["vision_queue"]
    API --> Q2["proposal_queue"]
    API --> Q3["render_export_queue"]
    Q1 --> W1["floorplan-vision-worker\n輸出 layout_json"]
    Q2 --> W2["proposal-agent-worker\n輸出 scene_json"]
    Q3 --> W3["render-export-worker\n渲染、PDF、匯出"]
    W1 --> DB["PostgreSQL + pgvector"]
    W2 --> DB
    W3 --> DB
    W1 --> OBJ["物件儲存\nDemo: MinIO\nProduction: AWS S3"]
    W2 --> OBJ
    W3 --> OBJ
```

## 6. 回退與提醒規則

- 大幅修改牆、門、窗、樑、柱：回第 4 步重新確認，原家具重新驗證。
- 家具無法合法放入：不硬塞；顯示原因、較小同類替代品或讓使用者第 6 步手動處理。
- PostgreSQL 暫不可用：第 6 步可回退到已驗證 JSON catalog；正式資料優先仍是 Kai PostgreSQL。
- 本機 IKEA GLB 備援：尚未完成，不可視為正式資料來源或提交大量 GLB。
- Graph RAG：只提供關係檢索與可追溯候選證據，不能取代 Ancai 的幾何驗證。
