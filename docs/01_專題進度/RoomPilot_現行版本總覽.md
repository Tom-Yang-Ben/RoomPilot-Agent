## 2. 定位與不做的事

**一句話定位:** 即時提案溝通平台。把使用者的平面圖與需求,在一次會談的時間內變成「AI 佈局、可手動微調、**5 分鐘內產出單視角照片級提案圖**」的提案流程,讓設計師與客戶快速對齊想像。(新五階段,待 Sunny 批准)

**明確不是(Out of Scope):**

- 不取代 AutoCAD / 3D Max 施工圖。
- 不做**任意角度**的 AI 生圖與自然語言換風格——寫實渲染只做「白模定格單一視角+色卡」的雲端渲染,結構由白模鎖定,無視角幻覺;換風格=換色卡,不是自然語言。(新五階段,待 Sunny 批准)
- 不做硬裝(天花板/管線/結構)、不做水電消防法規。
- 不做任意 CAD/PDF 全自動解析。
- 不做本機 3D 即時漫遊(7/16 已放棄:RTX 3060 跑整晚、卡頓)。
- 8/20 前不做帳號層(存專案用 projects 表,免登入;SaaS 預留=auth middleware+owner_id)、不做 Redis(快取=渲染履歷本身)。(7/18 裁決)

## 4. 核心流程(主線)

**新五階段(2026-07-16 會議共識,待 Sunny 老師批准;批准前 7/7 版七步流程仍為對外口徑)**

```
① 尺寸與空間辨識:上傳平面圖(DXF/PNG)→ AI 辨識格局 → 手動拉線定錨(兩點+實距,公分)
   → 房型下拉修正 → 節點切割(手動劃分開放式空間)
② 需求問卷(移到空間確認之後):基礎探討(必填,決定 AI 大方向)+ 進階探討(有預設值)
   雙層 80/20;特殊需求自由文字 → LLM 轉 JSON
③ 2D 傢俱佈局:AI Agent 依空間屬性+需求選件,引擎算座標(basic shapes,不涉風格)
   → 使用者拖曳/旋轉微調,在 2D 排除動線不合理與重疊
④ 3D 白模生成:2D 確認後自動生成(無風格),確認壓迫感與比例 → 手動調攝影機鎖定單一視角(取景)
⑤ API 高畫質渲染:白模定格+色卡 → 外部雲端 API → 單視角照片級 2D 圖,＜5 分鐘
   換風格=換色卡重打 API；使用者指定型號保持不變，未指定家具依色卡換選後由引擎重排
```

> 狀態依賴的可執行正本是 `project_models.py`、`project_store.py` 的 revision／版本血統與 `tests/test_project_api.py`；7/17 的 S1–S6／E0–E6 草案已於 2026-07-21 移出 repo 封存，不再作為現行契約。

**兩個關鍵設計:**

1. **需求拆兩層**:一般需求(人數/預算/風格偏好等)用**問卷勾選**直接收,不勞駕 LLM;**特殊需求**(自由文字)才用 LLM 辨識轉成 JSON,餵給 Agent 佈局。~~client_brief~~ **已廢除**,由「問卷結果 + 特殊需求 JSON」取代。
2. **風格重定義(7/19 組長決定)**:③ 先產生可確認的 2D 佈局；第⑤站用 6 風格 × 3 色系=18 張色卡換風格。**問卷明確指定的家具型號固定不換；未指定家具依色卡換成同類型風格候選，座標重新交由引擎驗證。** 每張最終 PNG 綁定白模版本、取景版本與色卡版本。

## 6. AI Agent 與引擎

### 6.1 Agent 做什麼

**Agent = 2D 佈局的大腦——理解需求、選件、定錨、失敗協商;引擎是它的手。** 吃「問卷 JSON+特殊需求 JSON+空間屬性(房型/節點切割/幾何,公分)」,產出選件與 layout_intent 語意提示(只說誰當錨點、靠哪面牆、誰優先——**不含任何座標數字**);放不下時走 recovery(換同型較小款/移除)與引擎協商重擺至收斂。風格視覺不歸 Agent(屬第⑤站色卡+渲染)。現行能力以 `backend/agent/`、`layout_service.py` 與對應測試為準。

### 6.2 引擎工具 + 現況

| 引擎 | 工具名 | 做什麼 | 現況 |
| --- | --- | --- | --- |
| 空間升維 | `upgrade_to_3d` | (前置:拉線比例)2D 平面圖 → 3D 白模 | 🟡 管線可動;拉線 UI 未做、3D 窗修正中 |
| 基礎配置 | `place_furniture` | 依需求放真實尺寸家具 | 🟡 邏輯有、tests/ 68 測試;實際結果依賴比例鏈 |
| 軟裝微調 | `adjust_furniture` | 手動拖曳(2D,MVP)調位置,引擎 validate 把關 | 🟢 `/api/projects/{id}/layout-2d/validate` 已由 2D 編輯器逐次呼叫，無效落點彈回；完整確認再做一次全場驗證 |
| Agent 提示鏈 | `layout_intent` / `recovery` | 擺位前語意提示;失敗協商換小款/移除 | 🟢 已接線有測試(`tests/test_agent_layout_intent.py`、`test_agent_recovery.py`) |
| 選件 | `layout_service` | 依房型/需求與型錄候選挑家具 | 🟢 問卷指定 ID 強制保留；本地規則可離線完成，OpenRouter 只可回候選 ID，非法／虛構 ID 一律剔除 |

> 介面契約:`backend/engine/schema.py` 的 `PLACE_FURNITURE_TOOL` / `ADJUST_FURNITURE_TOOL` 仍是 Agent ↔ 引擎的對接基礎;`examples/demo_agent_flow.py` 有 id 規則與失敗詞彙表。LLM 串接走 OpenRouter;key 統一控管制度不變(制度為舒媁提議);LLM 實作的**現行歸屬凍結中**,見 §11(歷史歸屬紀錄:v3.1 曾定「凡直接動到 LLM 的實作皆由楊舒媁負責,key 由柏彥統一控管」)。

### 6.3 碰撞 / 重疊 / 動線規則(劃分中)

現行引擎把「碰撞」一律視為違規,這不對 — 要劃分**合法重疊**:

- **電視** 應該可以放在**電視櫃上**(上下疊放合法)。
- **地毯** 應該可以墊在**所有家具下面**。
- 其他類似的家具疊放組合,逐類劃分規定。
- **擋門檢查:** 已把每扇門轉成 90 cm 虛擬障礙並納入自動配置與拖曳驗證；完整主動線寬度仍待規範。

## 8. 資料結構

- **一般需求(問卷結果):** 勾選項(人數、預算、風格偏好、機能等),前端直接結構化,不經 LLM。
- **特殊需求 JSON:** 使用者自由文字 → LLM 辨識轉成 JSON(🟡 intake 雛形),餵 Agent 佈局。
- **Scene JSON(單一資料源,公分):** 房間幾何+房型/節點切割+家具擺位+相機姿態;各狀態 `version` 欄位待加。所有讀寫經 server。
- **色卡 schema(✅ 已完成):** `catalog/data/taiwan_style_cards.json` v2.0——6 風格 × 3 色系,每卡 `card_id`+`name_zh`+`image_file`+`palette_hex×3`;圖檔 `server/static/style_cards/`。取代舊「風格界定 JSON(7,000 件 × 12 風格)」目標;型錄現行按 6 風格分類(`furniture_catalog_6styles_zh.json`)。
- **渲染履歷:** 每張渲染圖記錄(白模版本+取景版本+色卡)三欄;過期判定與快取皆用它。
- **平面圖辨識輸出:** DXF(WALL/WINDOW 圖層)+**交接 JSON**(門段+比例信心度;⚠ 第三套座標系:px+cm、原點左下,由 server 統一吸收)。
- **資料庫:** `PROJECT 1—N FURNITURE`(擺放實例掛 project_id)+ 需求 JSON 存放;擺放屬性必要欄位:`pos_x` / `pos_y` / `rotation`(對應 `schema.py` 的 `placed_to_dict`)。~~Redis 暫存層~~ 已裁決不做。
- **尺寸單位:引擎與 Python 業務層一律公分(2026-07-11 落地 ✅)**;殘餘公尺=四處遷移工項(見 §5.1 底座)。

## 9. 平面圖辨識(現行真實能力)

離線、不需 LLM。

- **DXF:** 🟢 解析 LINE / LWPOLYLINE / POLYLINE / ARC / CIRCLE / MLINE → 牆體;門 L 形+弧偵測、窗開口覆蓋率偵測;舊基準:窗 精準 89% / 召回 91%、門 過濾 ~100%(7/15 融合後窗召回 95%,見 PNG 條)。
- **PNG:** 🟢 已做,成功率高(灰階二值化 → 形態學 → 牆遮罩向量化 → 正交化輸出 DXF);**窗偵測 7/15 融合分割模型第二意見,召回 92→95%**;門靠交接 JSON 補(DXF 圖層只有 WALL/WINDOW)。
- **JPG / JPEG / BMP:** 🟡 已做,**成功率僅 ~50%** — **非 P0**,列 P1 續改。
- **批次輸出三套:** `data/testdata/dxf/`(辨識 DXF)、`data/testdata/dxf_scale/`(公分 DXF,外圍牆厚錨定自動比例)、`data/testdata/json/`(前端交接,px+cm 雙座標+scale 信心度)。
- **驗證資料:** `data/testdata/`(png+答案、door 樣式、dxf;**floor21=Demo 基準圖,已移植完成**)。

**限制:** 圖片無真實單位 → 自動比例僅供預設,**必須靠拉線比例(F2a)校正**;牆以軸向為主,斜/弧牆會掉。
