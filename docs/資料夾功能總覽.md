# RoomPilot 資料夾功能總覽

> 2026-07-16 全面重寫,對齊 ben 分支實際目錄(舊版列有 `furniture_engine/`、`sf3d/`、`web_fastapi/` 等已不存在的目錄,並誤稱外部索引不被執行期載入,均已更正)。新成員先看本文件,再進對應模組;單位契約與架構鐵律的完整版見根目錄 `CLAUDE.md`。

一句話心智圖:**`roompilot/` 是產品本體**(演算法+API+網站),`frontend3d/` 是由 8002 `/scene` 交付的 React/R3F 全流程原始碼,`tests/` 守契約,`testdata/`+`dataset/` 是燃料,`docs/` 是大腦,`scripts/`+`examples/` 是工具箱與參考範例。

## 一、頂層目錄地圖

| 目錄 | 功能 | 怎麼跑 / 入口 |
|---|---|---|
| `roompilot/` | **Python 主套件,所有正式後端與演算法**(見第二節) | 見各子模組 |
| `frontend3d/` | `/scene` 的 React 全流程與 R3F 編輯器:專案→辨識/同牆校尺→問卷→2D 配置→白模→提案;F6 拖曳邏輯來源(`Furniture.jsx`、`snap.js`) | 修改後 `npm run build`;正式操作只開 :8002 |
| `tests/` | 68 個 pytest:擺放/淨空/Agent 提示鏈/型錄契約/品質護欄 | `uv run pytest tests/ -v` |
| `scripts/` | IKEA 型錄維運管線:下載、清洗、驗證、GLB manifest、匯入 Postgres | 見 `scripts/README.md`(2026-07-16 起 uv 化) |
| `dataset/` | 素材原料(已進版控):`ikea_glb_db/`(GLB 1,808 檔)、`catalog_json/`(型錄 JSON 池+manifests)、`style_rag/`(風格池)、`floor_materials_pack_1/2`(地板材質) | 資料,不執行 |
| `testdata/` | 平面圖測試素材與評測答案(見第三節);**floor21=Demo 基準圖** | 資料,不執行 |
| `docs/` | SSOT、契約規格、狀態稽核、AI Harness 制度(見第三節) | 先讀 SSOT |
| `examples/` | `demo_agent_flow.py`(**活文件**,被 `engine/README.md` 引用為 Agent↔引擎介面範例+失敗詞彙表) | 只讀不依賴 |
| 根檔案 | `CLAUDE.md`/`AGENTS.md`(AI 協作規則)、`README.md`(快速上手)、`pyproject.toml`+`uv.lock`(依賴,extras:server/vision/catalog) | 新人先讀 README→SSOT |

## 二、`roompilot/` 主套件(對照主線七步:①上傳→②拉比例→③問卷→④升維→⑤擺位→⑥微調→⑦提案)

| 模組 | 主線 | 功能與關鍵檔 |
|---|---|---|
| `floorplan/` | ① | PNG/JPG→DXF:牆正交化+門窗偵測(規則管線+分割模型融合);`floorplan2dxf.py` 入口,eval 與變更史見同目錄 README;批次另產 `testdata/dxf_scale|json`。`vlm_judge.py`/`opening_classifier.py` 是**已接線的選配研究碼**(預設關),被主程式 import,勿刪 |
| `upgrade3d/` | ④ | DXF→3D 樓面 JSON(ezdxf):牆體聯集、房間=孔洞、窗段聚類合併;`dxf_parser.py`+`eval_window_merge.py` |
| `engine/` | ⑤⑥ | **家具座標唯一權威**:Shapely 碰撞+淨空七段檢查;`schema.py`=LLM tool 契約(v0.1);`dxf_room.py`=公尺→公分唯一邊界 |
| `agent/` | ⑤ | 擺位提示鏈(柏彥):`layout_intent` 語意提示+`recovery` 失敗修復;只出提示不出座標,已接線 `scene_service` |
| `catalog/` | ⑤ | `style_db.py`(型錄→引擎轉接,cm→m 邊界在此)+`data/` 六風格 10,550 件、台灣風格卡 |
| `catalog/data/舊友：12種風格與JSON/` | — | 12 風格封存夾,**但非全是死資料**:`external_furniture_import_index.json` 被 `server/main.py` 執行期載入、`ikea_furniture_style_database.json` 被契約測試鎖定——詳見該夾 README(2026-07-16 更正版) |
| `server/` | 全部 | 唯一 FastAPI:`main.py` 五頁(index/styles/library/scene/panorama)+約 20 個 API;`scene_service.py` 編排選品擺放、集中所有座標系轉換。`static/surface_assets/_import_all/` 名字像原料但**是活資產**(surface_catalog.json 引用 299 檔),勿搬勿刪 |
| `skills/` | ③ | `roompilot-llm/SKILL.md`(舒媁):對話式 intake/風格推薦的 LLM 行為契約;純規格文件,尚未被程式引用 |

## 三、資料與文件的內部結構

| `testdata/` 子目錄 | 內容 |
|---|---|
| `png/` → `dxf/` | 辨識輸入(21 張樓層圖)→ 管線輸出 DXF;`pngans/`=人工標注答案(評測 GT,**不可重生**) |
| `dxf_scale/` | **公分制 DXF**(外圍牆厚錨定比例)——給升維與前端的正式交接品 |
| `json/` | 前端交接 JSON:px+cm 雙座標+比例信心度;**座標系=左下原點、y 向上**(與引擎不同,勿直接混用) |
| `chk/` `door/` `pic/` | 檢查圖(管線可重生)、門偵測測試集、`pic/temp/`=server 的 PLAN_DIR |

| `docs/` 子目錄 | 內容(讀狀態文件前先看 DoD §0.1 可信度指引) |
|---|---|
| `01_專題進度/` | **SSOT《RoomPilot_現行版本總覽》**(範圍/P0/分工唯一正本)+ clearance 規則 |
| `02_復刻研究/`、`03_個人學習/` | 組長本地筆記與復刻原型——**不進版控** |
| `04_契約與規格/` | 前後端契約、Agent JSON Schema v1(目標格式非現況)、GUARDRAILS——可信度最高的一區 |
| `05_狀態與稽核/` | 狀態/稽核文件;過時者已移入 `archive/`(2026-07-16),留存者以 7/11 兩份稽核最新可信 |
| `ai-harness/` | 制度層:DEFINITION_OF_DONE、FAILURE_LOG(失敗教訓帳本)、TASK_TEMPLATES |
| `archive/` | 早期原型、作廢契約、過時狀態文件封存區 |

## 四、型錄資料流(更正版)

六風格正式型錄 `furniture_catalog_6styles_zh.json`(+外部索引 `external_furniture_import_index.json`)→ `roompilot.server.main` → `/api/furniture` 分頁 API → 家具資料庫頁與場景選品。模型是否可載入不是 JSON 的宣告值,而是 server 依實際本機 GLB、可讀 ZIP entry 或遠端 GLB URL 驗證後決定。
