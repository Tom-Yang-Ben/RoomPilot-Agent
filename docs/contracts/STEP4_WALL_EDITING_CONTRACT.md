# 第 4 步畫牆與結構編輯契約

狀態：待實作契約。本文約束第 4 步的手動畫牆、端點微調、刪牆與下游結構同步；不代表所有行為已上線。

## 1. 不可變結構與編輯範圍

第 4 步是唯一能改動牆、門、窗、樑、柱與房間邊界的流程。使用者完成確認後，第 5 步問卷與第 6 步單一家具配置不得修改這些結構。

畫牆模式只提供「畫牆」；不得顯示或推導「可拆牆方案」或結構方案預覽。

## 2. 畫牆互動

1. 使用者按「畫牆」。
2. 點第一點：顯示實心起點、虛線預覽與文字「起點已設定，請點終點」。
3. 游標移動：虛線尾端即時跟隨，讓使用者看得出牆將落在哪裡。
4. 點第二點：建立一段牆。牆長少於 25 cm 時不建立，顯示原因。
5. Escape、取消、切換工具或完成後清除草稿與虛線。

兩點都採平面圖座標，寫入 `wall_id`、`start_cm`、`end_cm`、`thickness_cm`、`height_cm`、`source: manual`。不要將畫牆起點誤當作門洞或門片資料。

## 3. 端點微調與吸附

建立後的牆兩端各有可拖曳端點。拖曳時顯示目前長度與對齊提示；可吸附到現有牆端點、牆線、門窗開口邊界。吸附僅是輔助，使用者仍可微調至非吸附位置。

每次放開端點前驗證：最小長度、不可與既有牆重疊、不可切穿門窗洞口、不可造成無法關閉的門洞。失敗時維持原位置並顯示具體原因。成功時標記結構變更待確認，後續房間面積、門窗 host wall 與 RAG payload 必須重算。

## 4. 刪牆雙重確認

選取牆後第一次按刪除不刪除，按鈕改為「再次點擊確認刪除牆」，並顯示該牆連接的門窗數與會影響的房間。第二次按下才執行刪除。取消、切換選取或逾時要清除待確認狀態。

刪除後若附著門窗失去 host wall，先列為待修正結構，禁止直接進第 5 步與第 6 步。

## 5. 門洞不變量

每一扇門只可產生一個 `door_id`、一個 `host_wall_id`、一段 `opening_range_cm` 與一個關門門片位置。開門弧線只用於判斷鉸鏈與開向；關門位置是沿門弧半徑落到同一段 `host_wall` 的門洞線，不可再拿弧線去推論另一面牆或產生第二個洞。

3D 生成前與第 6 步皆須驗證：

- 已確認門數 = 3D door mesh 數 = `doorOpening` 數。
- 每個 `door_id` 恰有一段洞口。
- 門片中心在線段洞口內，host wall 不可為空。
- 門洞範圍不可與窗洞、另一門洞重疊。

任一驗證失敗時，停止場景生成並在第 4 步標出對應門號及候選牆線，要求修正；不可安靜地少生門或另開洞。

## 6. 下游同步資料

第 4 步確認輸出需供問卷、家具引擎、RAG、生圖與 3D 共用：

```json
{
  "structure_revision": 12,
  "walls": [{"wall_id": "wall-20", "start_cm": [230, 520], "end_cm": [350, 520], "source": "manual"}],
  "doors": [{"door_id": "door-5", "host_wall_id": "wall-20", "opening_range_cm": [20, 108], "hinge_cm": [230, 520], "swing": "left"}],
  "windows": [],
  "beams": [],
  "columns": []
}
```

下游只讀此版本化結構快照。若 `structure_revision` 已變更，舊的方案、RAG 任務、家具碰撞結果與 3D 快取必須標為過期並重新計算，不能混用舊座標。
