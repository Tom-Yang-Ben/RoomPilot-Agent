# 十種空間問卷、家具與生圖需求契約

## 目的

本契約定義第 5 步問卷、RAG、家具引擎與第 6 步 2D+3D 的共同資料語意。所有消費端必須使用本文件的十種正式空間類型，不可自行增加 `DiningRoom`、`Study`、`MasterBedroom`、`KidsRoom` 或 `MultiPurposeRoom`。

UI 可用「主臥」、「次臥」、「兒童房」、「客餐廳共用」等文字協助使用者理解，但 API 必須使用下列正規代碼。家具引擎的 PascalCase 名稱不可直接送給目前 Python API。

| 家具引擎名稱 | API `room_type` | 狀態 |
| --- | --- | --- |
| `Hallway` | `hallway` | 已支援。 |
| `Bath` | `bathroom` | 已支援，名稱不同但語意相同。 |
| `Bedroom` | `bedroom` | 已支援。 |
| `Kitchen` | `kitchen` | 已支援。 |
| `LivingRoom` | `living_room` | 已支援，名稱不同但語意相同。 |
| `Balcony` | `balcony` | 已支援。 |
| `Entry` | `entryway` | 已支援，名稱不同但語意相同。 |
| `Storage` | `storage` | 已支援。 |
| `Stair` | `stair` | 不送家具 RAG 的例外；保留照明與淨空需求，交由第 6 步與生圖處理。 |
| `Garage` | `garage` | 已支援。 |

## 流程與責任

1. 第 4 步輸出已確認的房間、尺寸、牆、門、窗、樑柱與不可侵占區。
2. 第 5 步依房型與用途預選家具類型；使用者可增加、減少、選尺寸、輸入家具材質或風格形容詞。
3. 每間房按下「確認此房需求」後，立即把該房需求、格局限制與偏好送到 RAG 背景推薦；`Stair` 沒有可移動家具時標記 `no_furniture_rag_required`，不建立空的家具 RAG 工作。使用者可繼續下一房。
4. RAG 僅依 `slot_id`、尺寸、風格與偏好搜尋候選，不決定座標，也不得以名稱相近跨類型替換家具。
5. 第 6 步依真實 GLB 尺寸檢查門窗、走道、朝向及碰撞；放不下或缺 GLB 的原因與替代方案都在此步顯示，不得卡住第 5 步。
6. 廚房、浴室、陽台的大型固定設備與家電屬於生圖需求，不假裝成第 6 步的家具 GLB。

## 十種空間的用途與家具

| 正式空間 | 可選用途與預設功能 | 預選或可選家具 | 固定設備／生圖邊界 |
| --- | --- | --- | --- |
| `Entry` | 進出、換鞋、暫放物品 | 鞋櫃／衣帽收納、鏡子、穿鞋凳、門墊、窄收納、燈具 | 不產生大型家具；保留開門與進出淨空。 |
| `Hallway` | 通行、導引、展示 | 走道地毯、壁架、鏡子、壁燈、極窄收納 | 禁止大型家具；須保留主要通行寬度。 |
| `Bath` | 洗漱、如廁、淋浴、洗衣、收納 | 鏡櫃、小型收納、燈具、小地毯 | 洗手台、馬桶、淋浴／浴缸、洗衣機屬生圖與固定設備。 |
| `Bedroom` | 睡眠、更衣收納、閱讀／工作、兒童使用 | 床、衣櫃、床頭櫃、鏡子、燈具、地毯；勾工作才加書桌與工作椅；勾兒童才加兒童床桌椅與玩具收納 | 主臥／次臥／兒童房以用途與尺寸區分，不新增房型。 |
| `Kitchen` | 料理、用餐、收納、客餐廳共用 | 餐桌、餐椅、吧檯桌、餐邊櫃、層架、收納櫃、燈具 | 冰箱、爐灶、中島、流理台等屬固定設備與生圖需求。 |
| `LivingRoom` | 休憩、影音、閱讀／工作、客餐廳共用、兒童使用 | 沙發、沙發床、單人椅、茶几、電視櫃、邊桌、地毯、燈具、展示櫃與擺飾；依用途加書桌工作椅、餐桌餐椅、兒童桌椅與玩具收納 | 以門窗、電視牆與主要活動區決定家具朝向。 |
| `Balcony` | 曬衣、洗衣、休憩、植栽、戶外收納 | 戶外單椅、邊桌、長凳、戶外地毯、植栽擺飾、戶外收納、戶外燈 | 洗衣機、曬衣架等固定設備交給生圖；第 6 步只放可用 GLB 的小型家具。 |
| `Storage` | 收納、更衣、閱讀／工作、兒童用品整理 | 收納櫃、層架、書櫃、收納盒籃子、衣櫃、衣帽架、燈具；勾工作才加書桌工作椅；勾兒童才加玩具與兒童用品收納 | 可作為工作區第二優先房間，但不得妨礙儲物動線。 |
| `Stair` | 垂直通行、照明 | 僅允許照明；極窄壁架必須另外通過淨空檢查 | 預設空房，禁止可移動家具、地毯與大型擺飾。 |
| `Garage` | 停車、工具收納、工作維修 | 工作桌、層架、工具／收納櫃、收納系統、工作燈、必要鏡子 | 必須保留車輛與出入口動線；不得預選床、沙發、地毯、餐桌。 |

## 家具群組覆蓋表

下表覆蓋目前 `backend/spatial_data/rag/data/category_groups.json` 的全部 19 個群組。每個群組至少有一個主要歸屬空間；可跨房使用時仍需符合用途與安全規則。

| 家具群組 | 主要歸屬 | 額外允許條件 |
| --- | --- | --- |
| `sofa` | `LivingRoom` | `Bedroom`、`Storage` 或 `LivingRoom` 選兩種以上用途時可出現沙發床。 |
| `armchair` | `LivingRoom`、`Balcony` | `Bedroom`、`Entry` 可加單人椅或凳；不可放在走道與樓梯。 |
| `dining_chair` | `Kitchen` | `LivingRoom` 只有勾選客餐廳共用時才可加入，且必須搭配餐桌或吧檯桌。 |
| `office_chair` | `Bedroom` | 依序可在 `Storage`、`LivingRoom` 出現；必須搭配書桌。 |
| `stool_bench` | `Entry`、`Balcony` | `LivingRoom` 可作輔助座椅。 |
| `coffee_table` | `LivingRoom` | 必須搭配沙發或主要座椅區。 |
| `side_table` | `Bedroom` | 可作床頭櫃；`LivingRoom` 可作沙發邊桌。 |
| `dining_table` | `Kitchen` | `LivingRoom` 僅在客餐廳共用模式。 |
| `desk` | `Bedroom` | 依序可在 `Storage`、`LivingRoom` 出現，必須選閱讀／工作用途。 |
| `bed` | `Bedroom` | 多用途房間使用沙發床時，仍記錄為睡眠用途與床尺寸。 |
| `storage` | `Storage` | 可用於所有房型；依深度、門窗與走道限制決定是否合法。 |
| `wardrobe` | `Bedroom` | `Entry` 可顯示鞋櫃／衣帽架；`Storage` 可作衣物或雜物收納。 |
| `rug` | `LivingRoom`、`Bedroom` | `Entry`、`Kitchen`、`Balcony` 可用對應門墊／戶外款；樓梯禁止。 |
| `lighting` | 全部空間 | 樓梯僅照明；燈具要與天花形式、冷氣和樑柱規則相容。 |
| `mirror` | `Entry`、`Bedroom`、`Bath` | 走道可使用壁鏡，但不得侵占通行。 |
| `decor` | `LivingRoom`、`Balcony`、`Entry` | 依風格色卡提供；不可阻擋走道、門窗或工作面。 |
| `kids` | `Bedroom` | `LivingRoom` 可加入兒童桌椅與玩具收納；`Storage` 可加入兒童用品收納。 |
| `media` | `LivingRoom` | 不得自動放入臥室、走道、浴室、陽台、樓梯或車庫。 |
| `partition` | `Bedroom`、`Storage`、`LivingRoom` | 僅在同房勾選兩種以上用途時顯示；不得當作第 4 步結構牆。 |

## 新增家具 UI 規則

每個房間都必須有「新增家具」入口，且以分層分類呈現：

1. 本房推薦：依房型、用途、尺寸與全屋風格預選。
2. 主要家具：床、沙發、餐桌、書桌、衣櫃等錨點家具。
3. 收納：衣櫃、鞋櫃、櫃體、層架、壁架與收納籃。
4. 座椅與桌類：餐椅、工作椅、單人椅、凳、邊桌與茶几。
5. 燈具、鏡子與軟裝：地毯、燈、鏡子、擺飾、植栽。
6. 全部資料庫：可依名稱、材質、顏色、風格與分類搜尋。

從全部資料庫加入不屬於預設房型的項目時，問卷允許繼續，但須標示「第 6 步確認放置」，不可聲稱已合法放入。

## 家具數量、尺寸與成組提醒

- 使用者以加減按鈕選數量；每一件在第 6 步保有可定位的編號。
- 床必須先選尺寸家族，例如單人、小雙人、標準雙人、加大；不得只顯示型錄名稱。
- 選床時提醒可一鍵加入床頭櫃與床邊燈。
- 選書桌時提醒可一鍵加入工作椅與書櫃／收納。
- 選沙發時提醒可一鍵加入茶几、電視櫃或邊桌。
- 選餐桌時提醒可一鍵加入餐椅與餐邊櫃。
- 成組項目只做提醒與快速加入，不可強制勾選。

## 廚房、浴室與陽台的定位及生圖資料

### 廚房

問卷固定提供冰箱與爐灶兩項。系統先從第 4 步的牆、門、窗與可用區推導合法預設錨點；使用者可在平面圖拖曳或框選想要的位置，並選擇型式與補充文字。未修改時沿用合法預設。

### 浴室

問卷固定提供洗手台、馬桶、淋浴／浴缸與洗衣機需求。系統提供可調整的預設錨點與型式選擇。它們為生圖用的固定設備，不得在第 6 步以白模替代。

### 陽台

問卷可複選曬衣／洗衣設備、休憩、植栽與戶外收納。曬衣架與洗衣機屬生圖需求；可載入 GLB 的單椅、邊桌、植栽與小收納才交給第 6 步。

## RAG 與重新送出規則

- 每房確認後即送 RAG；`Stair` 若沒有可移動家具，確認後只寫入 `no_furniture_rag_required`，不建立空 RAG 工作。RAG 執行中不阻擋下一房。
- 修改用途、家具類型、數量、尺寸、材質關鍵字或固定設備定位後，舊 RAG 結果須標示過期，並重新送出該房需求。
- RAG 回傳缺 GLB、尺寸風險或不適配候選時，問卷只記錄風險；第 6 步必須顯示原因、定位、較小同類替代、替換與刪除操作。
- 問卷輸入的家具形容詞與固定設備需求必須與房間尺寸、門窗、結構限制一併送至後續生圖 Agent；不得用文字要求擴張房間或移除既有結構。

## 生圖 Agent handoff JSON

第 6 步產生場景時，後端會在 `sceneData.agent_generation_handoff` 建立初版 JSON。第 7／8 步送出生圖任務前，前端必須再次以目前 `scene_objects` 覆蓋每房的 `final_step6_furniture`，確保 Agent 取得使用者最後拖曳、旋轉與鎖定後的座標，而不是首次自動配置的位置。

每個 `rooms[]` 項目至少包含：

- `room_id`、`room_type`、`room_label`、`geometry`、`usage`
- `furniture_preference.tags` 與 `furniture_preference.description`
- `selected_catalog_furniture` 與 `final_step6_furniture`
- `generative_equipment`、`surfaces` 與本房 `rag` 工作結果

外部渲染呼叫的 `agent_generation_handoff` 會移除姓名、電話與地址等個人資訊。這份 JSON 是外部 Agent 的唯一配置資料來源；牆、門、窗、樑、柱皆視為固定結構，不可因方案 A／B 或生圖偏好改動。

## 驗收條件

1. 每個標準家具群組都能在上表找到至少一個主要歸屬房間。
2. 每個房間皆有新增家具入口及全部資料庫搜尋。
3. 走道與樓梯不會推薦或自動放入大型家具。
4. 廚房、浴室、陽台的大型固定設備在第 5 步有需求與定位資料，但第 6 步不產生假 GLB。
5. 除無可移動家具的 `Stair` 外，每房確認後可建立 RAG 工作；修改後舊結果不可繼續使用。
6. 第 6 步只顯示真實 GLB，並把缺 GLB、碰撞、門窗淨空、走道與朝向問題轉成可操作的待處理項目。
