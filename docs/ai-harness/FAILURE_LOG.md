# RoomPilot 失敗帳本

v1.0(2026-07-13)。**目的:同一個錯不犯第三次。** 開工前查相關條目;犯錯後照格式追加。

**升級為永久規則的門檻(三取一)**:重複發生兩次/單次嚴重損失/難被測試立即發現。達標就改 `.claude/rules/` 或 CLAUDE.md,並在條目標「已升級」。單次小失誤只記帳,不立規則。

**條目格式**(欄位無資料寫「不明」,不要編):

```text
### #N [一句話標題](日期)
症狀:
錯誤假設/無效修法:
根因:
有效修法:
教訓:
證據:[檔案路徑 / commit / 文件段落]
升級:[否 / 已升級→哪條規則]
```

### #1 引擎 25 測試全過,但實際擺放結果全錯(2026-07 持續中)
症狀:F5 基礎配置的擺位在真實樓面上明顯不對。
根因:平面圖無真實單位、F2a 手動拉比例未做,房間尺寸鏈根本未通——測試驗的是「邏輯自洽」,不是「輸入正確」。
有效修法:未解(等 F2a);制度面的修法是 DoD 第 3 層明文「通過只代表邏輯自洽,結果正確需尺寸鏈已通」。
教訓:**測試通過 ≠ 符合使用者需求**;宣稱完成要指明驗的是哪一層。
證據:SSOT §5.1(F5)、§6.2、§13。
升級:已升級 → DoD §0 通用判準。

### #2 scene 檢視器容器隱藏時初始化,場景全空白(2026-07-11)
症狀:切到 scene 頁面整個 3D 區黑/空白,無錯誤訊息。
根因:檢視器在 display:none 容器內初始化,拿到 0×0 尺寸。
有效修法:亮出後再初始化/補 resize。
教訓:前端「無錯誤但全空白」先查初始化時機與容器尺寸;這類 bug 不會被任何後端測試抓到。
證據:commit 9f9eb71。
升級:否(單次;frontend3d 重演一次就升級)。

### #3 引擎公分化後,邊界層雙重換算(2026-07-07)
症狀:engine 單位改公分後,scene_service/style_db 的數值被換算兩次。
根因:單位邊界改了,但下游換算點沒有同步盤點——「唯一邊界」被改成兩個邊界。
有效修法:cd11ed7 消除雙重換算;CLAUDE.md 明文邊界(dxf_room=公尺→公分唯一邊界、cm→m 在 style_db)。
教訓:動單位/座標系時,必須先 grep 全部換算點再改,改完列受影響檔案清單。
證據:commit cd11ed7、b58d53e;CLAUDE.md invariants。
升級:已升級 → CLAUDE.md invariants(單位節)。

### #4 「missing_model_count=0」宣稱被稽核推翻,實缺 4100 筆 GLB(2026-07-11)
症狀:7/6 文件宣稱 GLB 缺漏已補齊歸零;7/11 稽核實測 10361 筆家具只有 6349 筆有可用 GLB。
錯誤假設:索引檔有記錄=檔案存在。
根因:`external_furniture_import_index.json` 的 zip_entry 前綴與實際目錄名不符(`downloaded-files/` vs `downloaded-files(furniture)/`),且部分檔案根本不在任何可讀 zip。
教訓:**「已補齊」這種話必須附可重跑的清點指令與輸出**;索引 ≠ 實物。
證據:Git 歷史中的 `EXTERNAL_GLB_SOURCE_AUDIT_2026-07-11.md` 推翻 `docs/archive/MODEL_PIPELINE_STATUS.md` 的結論；前者已於 2026-07-21 移出現行 repo 封存。
升級:已升級 → `.claude/rules/verification.md`。

### #5 GLB 檔名撇號不一致,32 個模型無聲缺失(2026-07-06 前)
症狀:32 件家具模型載不出來。
根因:檔名 `Children_s` 與索引裡的 `Children's` 撇號不一致。
有效修法:補檔 zip + 修復腳本(文件記為 `scripts/repair_missing_glb_paths.py`,**該腳本未入倉、已佚失**——scripts/ 曾被 gitignore 整目錄忽略;修法不可重跑,僅存紀錄)。
教訓:跨來源資料對接要驗「實際能開啟」而不是「路徑字串存在」;特殊字元(撇號/空格)是高發區。
證據:`docs/archive/MODEL_PIPELINE_STATUS.md` §缺失 GLB 補檔紀錄。
升級:否(與 #4 同族,#4 已立規則)。

### #6 F6 拖曳曾被判「完成」,後被更正為未達標(2026-07-06→07-07)
症狀:v2.0 記 F6 拖曳雛形完成;v3.0 更正:手動微調沒修好、體驗未達標。
根因:「做出來了」和「能用」之間沒有驗收標準——沒有人用完整使用者路徑實測過。
教訓:互動類功能的完成=GUARDRAILS 四要件全過(畫面/互動/資料/驗收),缺互動實測就不許標綠。
證據:SSOT 變更紀錄 v2.0/v3.0、§11.1。
升級:已升級 → DoD 第 6 層(frontend3d 唯一驗證方式=瀏覽器實測)。
