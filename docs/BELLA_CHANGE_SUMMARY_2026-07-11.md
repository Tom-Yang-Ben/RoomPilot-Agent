# Bella 分支目前改動摘要

更新日期：2026-07-11  
分支：`bella`

## 1. 本次改動目標

目前 `bella` 以 RoomPilot 網頁版展示流程為主，整合家具資料、六種住宅風格、牆面與地板材質、家具挑選、需求問答及 Three.js 3D 場景。主要流程為：

```text
首頁與功能介紹
→ 風格與生活色調選擇
→ 家具資料庫挑選家具
→ 3D 場景補充空間需求
→ 產生並微調室內配置
```

## 2. 家具與 GLB 資料

- 將家具資料整理為目前使用的六種風格：北歐、日式、現代簡約、奶油、工業、美式。
- 新增 `furniture_catalog_6styles_zh.json`，統一家具中文名稱、類型、尺寸、顏色、材質、風格候選與 GLB 路徑。
- 舊版十二風格 JSON 移到封存目錄，不再作為目前網站主資料來源。
- 整合 IKEA、ABO、Sketchfab 與補缺 GLB，並保留模型來源與缺漏稽核文件。
- 新增顏色、材質與角色缺漏候選資料，供後續資料清洗與人工確認。
- 家具模型由後端統一解析實體檔案或 zip entry，前端只使用 `/api/furniture/{id}/model`。

## 3. API 與載入效能

- 將原本所有頁面共用的完整 `/api/site-data` 拆成頁面專用 API：
  - `/api/home-data`
  - `/api/styles`
  - `/api/furniture`
  - `/api/furniture/{id}`
  - `/api/scene/bootstrap`
- 家具 catalog 在伺服器端建立記憶體快取，避免每次換頁都重新合併全部家具。
- 家具資料庫改為後端搜尋、篩選與分頁，每頁只回傳 24 件家具。
- `/api/furniture` 支援空間、類型、風格、尺寸、顏色、材質與關鍵字條件。
- 顏色與材質篩選會合併中英文同義值，例如 `white` 與「白色」使用同一個繁中選項。

## 4. 首頁

- 保留 RoomPilot 黑色背景、星點動畫與統一導覽列。
- 首頁標題、流程說明與五個功能圖示重新排版。
- 上下兩組流程圖示建立對應互動；滑鼠移到上方功能時，下方對應步驟同步顯示。
- 調整桌機與手機響應式版面。

## 5. 風格頁

- 新增六種風格、每種三張生活情境色調卡，共 18 張。
- 風格卡改為圖文交錯排列，加入漸層背景與繁中生活情境解析。
- 風格示意圖與標註重新整理，避免以採光或窗外景色作為風格理由。
- 選擇色調後會保存到 `sessionStorage`，可帶入 3D 場景。
- 整理牆面生成材質、牆面資料庫與地板資料庫推薦，並依風格篩選。
- 牆面與地板維持不同資料來源與分類，不互相混用。

## 6. 家具資料庫

- 家具頁改為左右工作台：左側挑選家具，右側顯示單件家具 Three.js 3D 檢視。
- 首屏包含空間選擇、家具類型圖示、關鍵字與風格／尺寸／顏色／材質篩選。
- 家具卡顯示模型預覽、繁中名稱、尺寸、風格、材質與顏色。
- 家具卡支援收藏、加入本次方案清單及帶入 3D 場景。
- 淺色家具依資料與模型狀態切換深色預覽背景，提高辨識度。
- 預設只顯示已確認可載入 GLB 的家具，並由後端分頁取得。
- 保留黑色外層背景與星點動畫，手機版不產生水平溢出。

## 7. 3D 場景與需求流程

- 場景流程改為上傳平面圖、空間需求、風格選擇、家具偏好及生成場景。
- Step 2 同時提供固定選項與聊天補充欄位，使用者可填寫特殊需求。
- 房間類型、寬度及深度不再直接預設；缺漏時會要求使用者填寫或確認使用預設值。
- 從家具資料庫進入場景時，先顯示已選家具清單，並可移除或讓系統保留主要家具。
- 生成前檢查空間資料與家具需求；若沒有可放入家具，不再只顯示空白場景。
- 牆面與地板選擇可帶入 Three.js 材質，使用 repeat wrapping 呈現連續木紋與磁磚。
- 加入家具選取、地板輔助框、前後左右微調、左右旋轉、貼牆與房間邊界限制。
- 3D viewer 維持 XYZ 顏色提示，並改善室內視角與家具清單獨立捲動。

## 8. Agent 與資料契約

- 新增 Agent intake 流程與前後端 JSON 契約文件。
- 家具候選保留 `requirement`、`furniture_candidates` 與工具 schema 的轉換層概念。
- 3D 生成會優先使用家具資料庫傳入的精確 `furniture_id`，再補足其他需求家具。
- 已加入 OpenRouter provider 狀態檢查與 `.env` 金鑰讀取流程；`.env` 不進版控。

## 9. 測試與驗證

- 新增家具 catalog、GLB 解析、六風格資料、生活色調卡、家具資料庫 Mode 1、場景需求流程等測試。
- 目前完整測試結果：`49 passed`。
- `library.js`、`scene.js` 等主要前端腳本已通過語法檢查。
- 家具資料庫已用 1655 × 927 桌機畫面及手機寬度實際檢查。

## 10. 尚待下一批處理

- 家具資料庫的類型名稱與圖示要依使用者選擇的空間動態更換，不能固定使用客廳分類。
- 「裝飾品」必須排除燈具；燈具維持獨立分類。
- 冰箱、洗衣機、烤箱與其他家電不顯示在家具資料庫，只在 3D 場景依空間與需求配置。
- `/scene` Step 2 的已選風格要新增「更換風格」，並保留已填空間資料與特殊需求。
- 更換風格後需重新評估家具相符度，由使用者選擇保留或同風格替換，不直接刪除家具。
- 持續依 GLB 缺漏稽核清單補齊剩餘模型與資料欄位。
