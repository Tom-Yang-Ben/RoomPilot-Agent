# 3D 房屋場景建置流程（可復現）

> 從 `.dxf` 平面圖到 react-three-fiber 3D 場景的完整建置邏輯，據原始碼整理、非推測。
> 目標讀者：想在別的 codebase 復刻這條 pipeline 的人。
> 對應原始碼：`backend/app/dxf/`、`frontend/src/api/floorplan.ts`、`frontend/src/scene/`、`frontend/src/App.tsx`。

---

## 0. 一句話總覽

```
.dxf ──解析──▶ FloorPlan(mm) ──API 信封──▶ FloorPlanCm(cm) ──純函式──▶ SceneModel ──r3f──▶ three.js meshes
      後端 Python                    邊界 ÷10                buildSceneModel        FloorPlanScene
```

**設計骨架（復刻時務必照抄的兩條原則）**：

1. **幾何運算全在純函式層**（`scene/geometry.ts`），可用 vitest 單測；r3f 組件只做「描述 → mesh」與材質，不算幾何。
2. **單位只在 API 邊界換算一次**（mm → cm，÷10），場景內不再乘除。所有數值常數集中在 `DEFAULT_SCENE_CONFIG`，禁止散落硬編碼。

## 1. 座標系與單位約定（最關鍵，先讀）

| 項目 | 約定 |
| :--- | :--- |
| 後端單位 | 公厘 mm（與 DXF 對齊，`$INSUNITS` 換算後統一為 mm） |
| 前端單位 | 公分 cm（`1 three.js unit = 1 cm`），API 邊界 ÷10 一次 |
| 平面 → 世界 | 平面 `(x, y)` → 世界 `[x, 0, -y]`（Y-up；俯視時方位與圖紙一致） |
| 線段方向角 | `θ = atan2(dy, dx)`，直接當 mesh 的 `rotationY` |
| 高度軸 | 世界 Y，地板在 `y=0`，牆從 `y=0` 長到 `wallHeightCm` |
| 座標軸指示 | 場景固定顯示 `AxesHelper`（原點 = DXF 原點，X 紅 / Y 綠 / Z 藍） |

**為何 `y → -z`**：DXF 平面 y 軸朝「北/上」，three.js 俯視時 -z 朝螢幕上方。把平面 y 映到世界 -z，俯視畫面方位才與原圖一致。**這個負號貫穿全部幾何函式**，復刻時每一處 `worldFromPlan` 都不能漏。

## 2. 資料流總圖

```
UploadPanel ──FormData(file)──▶ POST /api/dxf/parse ──▶ 統一信封 { success, data, error }
                                                             │ data = FloorPlan(mm) 序列化
api/floorplan.ts ◀───────────────────────────────────────────┘
   │  解信封(error 拋 FloorPlanApiError) + mm→cm(÷10) + snake_case→camelCase

   │ SceneModel { boxes[], polygonWalls[], floor, cameraPose }

   ▼

```

## 3. 後端：DXF → FloorPlan(mm)

檔案：`backend/app/dxf/{parser,layers,units,models}.py`、端點 `backend/app/api/dxf.py`。

### 3.1 圖層分類（`layers.py`）

只認 **wall / window / door** 三類，其餘（DIMENSION、TEXT、浮水印 `PinCAD.com` 等）一律視為雜訊丟棄。

- **完整 token 比對**，非子字串：圖層名先用 `re.findall(r"[a-z]+")` 切成 token 集合（`"Wall_SYN"` → `{wall, syn}`、`"wall01"` → `{wall}`），再看是否含關鍵字。避免 `outdoor` 誤判成 door、`drywall` 誤判成 wall。
- **優先序**：`window > wall > door`。圖層名同時含多關鍵字（如 `WALL-WINDOW`）取先者。
- case-insensitive。

```
classify_layer(name) -> "wall" | "window" | "door" | None
```

### 3.2 單位換算 + 尺度防線（`units.py`）

DXF header `$INSUNITS` 碼 → mm 係數：`1=inch(25.4) 2=feet(304.8) 4=mm(1) 5=cm(10) 6=m(1000)`。
`0`（無單位）或未知碼 → `UnsupportedUnitError`（明確報錯，**不默默當 mm**，否則下游 3D 尺度全錯）。

**尺度防線 `resolve_scale`**（處理宣告單位錯誤的圖）：

1. 宣告 scale 換算後短邊 ∈ `[2m, 100m]` → 直接採用，`notice=None`（絕大多數檔）。
2. 否則試候選 scale `(1, 10, 25.4, 304.8, 1000)`，取換算後短邊落合理帶且最接近 `10m` 者，附 `notice` 說明「已依幾何推斷」。
3. 全不命中 → `DxfParseError`（尺寸不合理）。

> 合理住宅短邊帶：`< 2m` 是柱子/碎塊，`> 100m` 是整棟社區或單位錯亂。

### 3.3 實體 → 線段 / 封閉環（`parser.py`）

走訪 modelspace，納入的實體型別：`LINE / LWPOLYLINE / POLYLINE / MLINE`。其餘略過。

- **TEXT / MTEXT**：不分圖層都收（圖層命名混亂），做空白正規化後存為 `TextLabel`（房間功能辨識用）。
- **牆層的封閉折線** → 保留**頂點環**（`_closed_ring`，多邊形擠出用），**不**攤成線段（避免前端雙重畫牆）。首點不重複，退化（< 3 點）則丟棄。
- **其餘（含窗/門層的封閉折線）** → 攤成線段 `(x1,y1,x2,y2)`。
- **弧段（bulge）**：LWPOLYLINE / 封閉 POLYLINE 一律經 `ezdxf.path.make_path().flattening(tol)` 正確攤平，容差 `_ARC_SAGITTA_MM = 2.0mm`（弧與弦最大距離，室內尺度肉眼不可辨）。
- **MLINE**：無簡單頂點 API，`virtual_entities()` 爆炸成 LINE 再取端點。單一實體失敗只記 log、不拖垮整檔。
- **兩趟收集**：先以宣告 scale 收一次 → 若尺度防線改了 scale，以正確容差**重收一次**（弧牆攤平密度才正確）。

**牆體表示法分兩派**（探測 `./CAD` 30 檔得出）：

| 來源 | 牆表示 | 前端建牆路徑 |
| :--- | :--- | :--- |
| `floorNN`（21 檔） | 封閉 LWPOLYLINE → `wall_polygons` | 多邊形擠出 `openingInfill` |
| centerline / PinCAD（9 檔） | 散 LINE → `walls` | 線段掃出 `windowPieces` |

### 3.4 輸出資料格式（`models.py` / API 信封）

```python
@dataclass(frozen=True)
class FloorPlan:            # 全部不可變(coding-style: 不可變性 CRITICAL)
    walls:         tuple[Segment, ...]          # 散線牆
    wall_polygons: tuple[Ring, ...]             # 封閉牆環(首點不重複)
    windows:       tuple[Segment, ...]
    doors:         tuple[Segment, ...]
    bbox:          tuple[float, float, float, float]  # (min_x,min_y,max_x,max_y),只由結構決定
    unit_name:     str                          # "inch"/"feet"/"mm"... 供顯示
    texts:         tuple[TextLabel, ...] = ()    # 圖面文字,房間辨識訊號源
    unit_notice:   str | None = None            # 尺度防線推斷時的說明
```

- `bbox` **只由結構幾何決定**，`texts` 不參與（圖外標題不得撐大 bbox）。
- 至少要有 wall/polygon/window/door 之一，否則 `NoStructureError`。

**API 端點 `POST /api/dxf/parse`**（`api/dxf.py`）：

- 統一信封 `{ success, data, error }`（`patterns.md`）。
- 上傳上限 20MB（`413`）；壞檔/不支援單位/無結構 → `400`；未預期 → `500`（不外洩堆疊）。
- 座標輸出為 **mm**；`wall_polygons` 序列化為 `[[[x,y],...], ...]`。

## 4. API 邊界：mm → cm（`api/floorplan.ts`）

前端唯一的單位換算點。`parseDxf(file)`：

1. `POST /api/dxf/parse`（FormData）。連線失敗 → `FloorPlanApiError('無法連線後端…')`。
2. 解信封：`success=false` 或 `data=null` → 拋 `FloorPlanApiError(error)`。
3. **mm → cm（÷10）** 逐座標；`snake_case` → `camelCase`（`wall_polygons` → `wallPolygons`、`unit_notice` → `unitNotice`）。
4. 回傳 `{ plan: FloorPlanCm, raw: RawPlanMm }`。`raw` 原封保留給下游房間分割/擺放 API（它們吃 mm，不做 cm 往返）。

```ts
type FloorPlanCm = {                          // 全 readonly
  readonly walls: readonly Segment[]          // {x1,y1,x2,y2} cm
  readonly wallPolygons: ReadonlyArray<readonly Vec2[]>   // [ [x,y], ... ]
  readonly windows: readonly Segment[]
  readonly doors: readonly Segment[]
  readonly bbox: readonly [number, number, number, number]
  readonly unitName: string
  readonly unitNotice: string | null
}
```

## 5. 場景幾何建置（核心）：`buildSceneModel(plan, cfg)`

檔案：`scene/geometry.ts`（純函式）、`scene/config.ts`（數值）。輸出：

```ts
type SceneModel = {
  boxes:        BoxDesc[]       // 牆/玻璃盒(線段掃出 + 開口)
  polygonWalls: PolyWallDesc[]  // 多邊形牆環 + 高度
  floor:        BoxDesc
  cameraPose:   { position, target }
}
type BoxDesc = { kind:'wall'|'glass'|'floor', center:[x,y,z], size:[沿段長,高,厚], rotationY }
```

### 5.1 SceneConfig — 唯一數值來源（`config.ts`）

```ts
DEFAULT_SCENE_CONFIG = {
  wallHeightCm: 280,          // 牆高 / 天花高
  wallThicknessCm: 12,        // 線段牆厚
  window: { sillCm: 90, headCm: 210 },   // 窗台 / 窗頂高
  windowOverrides: {},        // 以「群聚後窗索引」覆寫個別窗 sill/head(自然語言調整掛點)
  door:  { sillCm: 0, headCm: 210 },     // 門:底 0(通行)
  glassThicknessCm: 2,
  epsilonCm: 0.2,             // 補實牆帶厚度內縮 / 玻璃微露,防 z-fighting
  minWindowWidthCm: 30,       // 群聚後代表段短於此 = 符號雜訊,丟棄
  floorMarginCm: 50,          // 地板外擴
  axesSizeCm: 200,            // RGB 座標軸長度
}
```

### 5.2 線段牆（`segmentWallBox`）

散線牆每條 → 一個盒：

```
center = [mid_x, wallHeightCm/2, -mid_y]
size   = [segLen, wallHeightCm, wallThicknessCm]
rotationY = atan2(y2-y1, x2-x1)
```

### 5.3 窗群聚（`clusterWindows`，Union-Find）

DXF 的窗常是**多條平行線**（`floor01`：48 線 ≈ 8 窗），必須群聚去重，否則玻璃疊片閃爍。

- **合併條件**（兩線段 union）：中點距離 `≤ 30cm` **且** 方向夾角 `≤ 10°`（mod 180°）。O(n²) 配對，中點/方位角預先算好。
- **代表段** = 群內**最長**線段；代表段長 `< minWindowWidthCm(30)` 的群**整組丟棄**（符號端線）。
- **索引穩定性**：依代表段中點 `(round(x*10), round(y*10))` 排序後編號 → 同圖多次渲染索引不變（`windowOverrides` 的 key 才穩定）。
- 門線段沿用**同演算法**。

### 5.4 開口幾何：兩條路徑（依牆表示法二選一）

**切換開關**：`infill = polygonWalls.length > 0`。一張圖只要有多邊形牆，**全部開口**走 `openingInfill`；否則全走 `windowPieces`。

#### 路徑 A — 線段牆：`windowPieces`（完整開口）

沿代表段，厚度軸取 `wallThicknessCm`，補實厚 `infillThick = wallThicknessCm - 2·epsilonCm`：

| 片 | 條件 | 高度範圍 | 厚 |
| :--- | :--- | :--- | :--- |
| 玻璃 | `withGlass && head>sill` | `sill..head` | `glassThicknessCm` |
| 窗台下補實 | `sill > epsilon` | `0..sill` | `infillThick` |
| 窗頂上補實 | `head < wallHeight-epsilon` | `head..wallHeight` | `infillThick` |

門：同機制、用 `door` 規格、`withGlass=false`（真空洞，只留門楣以下通行）。

#### 路徑 B — 多邊形牆：`openingInfill` + `estimateProfile`（連續牆 + 貼玻璃）

多邊形牆的洞**由資料自帶**（不引入 CSG）。做法是「補一段與左右鄰牆同厚同心的連續牆跨過開口縫，窗再貼一片玻璃」。

`estimateProfile(seg, polygons, cfg)` — 由開口線段兩端鄰近的牆多邊形頂點推定牆斷面：

- 建立開口的沿段軸 `u`、法向軸 `n`。掃所有多邊形頂點，投影到 `(u, n)`。
- 只取：法向 `|dn| ≤ 40cm`（排除垂直牆遠角）**且** 距開口任一端點 `≤ 50cm` 的頂點。
- `thicknessCm = maxDn - minDn`（法向 spread）、`offsetCm = 中點`、`startU/endU` = 沿段搭接範圍（可越過 `[0,len]` 疊進鄰牆消縫）。
- spread `< 3cm`（單一外框多邊形、開口離牆太遠）→ **fallback** 回 `wallThicknessCm`、貼線段。

`openingInfill`：

- `wallBottom = withGlass ? 0 : head`（**窗**=全高連續牆 + 玻璃貼片；**門**=只補門楣 `head..天花`，底下留通行口）。
- 連續牆：沿 `startU..endU`、高 `wallHeight-wallBottom`、厚 `profile.thickness`、中心線沿法線偏 `offset`。
- 玻璃（窗）：`sill..head`、厚 `profile.thickness + 2·epsilon`（兩面各微露，避免與牆共面閃爍）。

### 5.5 多邊形牆擠出（`buildPolygonWallGeometry`）

```
THREE.Shape(平面 x,y 頂點環) → ExtrudeGeometry(depth = heightCm, bevel 關)
→ geom.rotateX(-π/2)   // 平面(x, y, 擠出 z=h) → 世界(x, h, -y)
```

**不變式（單測鎖定）**：`100×100cm` 環、牆高 280 → 世界 bbox `x∈[0,100]`、`y∈[0,280]`、`z∈[-100,0]`。復刻時用這條驗證旋轉方向沒錯。

### 5.6 地板（`floorBox`）

bbox 各向外擴 `floorMarginCm(50)`，薄盒 `y ∈ [-5, 0]`（`FLOOR_THICKNESS_CM=5`）：

```
center = [(minX+maxX)/2, -2.5, -(minY+maxY)/2]
size   = [width + 2·margin, 5, height + 2·margin]
```

### 5.7 相機取位（`fitCameraPose`，不寫死）

各檔尺度差異大，相機依 bbox 推算：

```
target = [(minX+maxX)/2, 0, -(minY+maxY)/2]
span   = max(width, height, 100)          // MIN_CAMERA_SPAN_CM=100
d      = span * 1.2                        // CAMERA_DIST_FACTOR
position = [ target.x + d*0.7,  d*0.9,  target.z + d*0.7 ]   // XZ 0.7 / Y 0.9
```

45° 俯視、對角斜看。`App.tsx` 以 `cameraPose.position` 當 `<Canvas key>`：換檔重掛 Canvas，初始相機才對準新 bbox。

## 6. 場景組裝：SceneModel → three.js（`FloorPlanScene.tsx`）

r3f 薄組件，只做映射與材質：

- `BoxDesc` → `<mesh position rotation material><boxGeometry args={size}/></mesh>`。
- `PolyWallDesc` → `buildPolygonWallGeometry` 產 geometry（`useMemo`，卸載時 `geometry.dispose()`——r3f 不會自動釋放 prop 傳入的幾何）。
- 地板一個 Box。

**材質**（`materials.ts`，`MeshStandardMaterial`，依 `kind` 選）：

| kind | 色源 | 備註 |
| :--- | :--- | :--- |
| wall | `palette.colors.wallHex` | |
| glass | `palette.colors.glassHex` | `transparent, opacity 0.35, depthWrite:false` |
| floor | `palette.colors.floorHex` | |

- 每次換色票/全屋上色 → `makeMaterialSet` 建**全新一組**，舊組 `disposeMaterialSet` 釋放（不用模組級單例）。`overrides.global` 的 hex（自然語言全屋上色）蓋掉色票色。
- **色票庫**（`palettes.ts`）：4 風格（北歐/日式無印/工業/現代簡約）× 各 3 組，每組 `wall/floor/glass/accent` hex。`findPalette(id)` 查無回預設 `scandi-1`（UI 永不因壞 id 崩潰）。

**燈光 / 環境**：

```
<axesHelper args={[axesSizeCm]} />                    // RGB 座標軸
<Environment preset="apartment" />                    // IBL,path tracer 主光源 + 即時柔光
<ambientLight intensity={0.7} />
<directionalLight position={[500,800,300]} intensity={1.2} />
```

## 7. 頂層組裝與三階段流程（`App.tsx`）

**三階段**（`phase = plan===null ? 'upload' : confirmed ? 'scene' : 'adjust'`）：

```
upload  ──上傳解析──▶  adjust(2D 擺放調整,未生成 3D)  ──使用者確認──▶  scene(3D 場景)
```

上傳成功 `handleParsed` 後**並行**觸發（皆為附加層，失敗不擋主流程）：

- `furnishTwoStage(raw, style)` → 選件 + 擺位（家具 placements）。
- `segmentRooms(raw)` → 房間分割（房型標註）。

3D 場景（`scene` 階段）的 `<Canvas>`：

```tsx
<Canvas
  key={cameraPose.position.join(',')}          // 換檔重掛,對準新 bbox
  gl={{ preserveDrawingBuffer: true }}          // 寫實渲染存 PNG 才不全黑
  camera={{ position: cameraPose.position, fov: 50, near: 1, far: 100000 }}
>
  <FloorPlanScene model config palette surfaceOverrides />
  <RoomFloorPatches ... />        {/* 附加層,見 §8 */}
  <RoomWallLining ... />
  <FurnitureLayer placements />
  <CameraHeadingTracker headingRef />
  <OrbitControls makeDefault target={cameraPose.target} />
  <PathTracerView enabled={realistic} />
</Canvas>
```

- `near:1, far:100000`：cm 尺度下跨距可達數千，遠平面必須夠大。
- `CameraHeadingTracker`：每幀把視線方位角寫進 ref（不觸發重渲染），自然語言「左邊的床」類指令換算用。`headingDegFromDirection(x,z)=atan2(x,-z)`（0=北、順時針）。

## 8. 附加層（在房屋外殼上疊加，非核心外殼）

這些不屬「房屋外殼」建置，但構成完整場景，復刻順序可延後：

| 層 | 檔案 | 做法摘要 |
| :--- | :--- | :--- |
| 逐房地板貼片 | `RoomFloorPatches.tsx` | 房間多邊形 → 薄片貼地,依 `floorByRoom` 上色 |
| 逐房牆襯薄殼 | `RoomWallLining.tsx` + `ringSnap.ts` | 沿房環每邊生垂直 quad(`buildRingLiningGeometry`,無頂底蓋、DoubleSide)。房環是柵格描邊有量化縫 → `snapRingToWalls` 逐邊沿外側法線吸附最近平行真牆面、內縮 eps |
| 家具 | `FurnitureLayer.tsx` | 每件 `useGLTF(glbUrl)`,`footprintScale` 非等比縮放(x→寬、z→深),bbox 中心對齊 placement、底面貼 `y=0`。載入中/404 → 同 footprint **灰盒替身**(ErrorBoundary + Suspense,不穿透弄垮 app) |
| 寫實渲染 | `render/PathTracerView.tsx` + `pathTracer.config.ts` | three-gpu-pathtracer 漸進式:`targetSamples 300, bounces 5, envPreset 'apartment', renderScale 1`(拖動時降到 0.5)。低硬體需求(不需高階 GPU) |

> 家具灰盒 = GLB 404 降級,查 `dataset`/`catalog` 路徑,非前端 bug。

## 9. 復現檢查清單

照這順序復刻，每步都有可驗證的產出：

- [ ] **DXF 解析**：圖層 token 白名單(wall/window/door)、`$INSUNITS` 換算 + 尺度防線、實體攤平(弧段容差 2mm)、牆封閉環另存 `wall_polygons`。輸出 mm 的 `FloorPlan` + 統一信封。
- [ ] **API 邊界**：解信封 + mm→cm(÷10) + snake→camel。錯誤轉友善訊息。
- [ ] **SceneConfig**：所有數值集中一處(牆高 280、厚 12、窗 90/210、門 0/210…)。
- [ ] **座標**：`(x,y)→[x,0,-y]`、`rotationY=atan2(dy,dx)`,全程一致。
- [ ] **窗群聚**：Union-Find(≤30cm & ≤10°)、最長代表段、丟 <30cm、中點排序穩定索引。
- [ ] **開口**：`polygonWalls>0` → `openingInfill`(斷面推定 + 連續牆 + 貼玻璃);否則 `windowPieces`(玻璃 + sill/head 補實)。門不放玻璃。
- [ ] **多邊形牆**:Shape + Extrude + `rotateX(-90°)`。用 `100×100` 環 bbox 不變式驗方向。
- [ ] **地板 / 相機**:`floorBox`(bbox+margin,y∈[-5,0])、`fitCameraPose`(span×1.2,XZ 0.7/Y 0.9)。
- [ ] **組裝**:描述→mesh、材質依 kind、`axesHelper` + `Environment('apartment')` + ambient 0.7 + directional 1.2。Canvas `fov 50 / near 1 / far 100000`、`key` 綁相機位。

### 關鍵不變式（測試鎖定，復刻後應同樣成立）

- `100×100cm` 多邊形牆(高 280)→ 世界 bbox `x[0,100]`、`y[0,280]`、`z[-100,0]`。
- 窗符號多線 → 群聚成 1 窗;兩窗 → 2 群;短於 `minWindowWidth` 的群丟棄;索引隨中點穩定排序。
- `windowPieces`:門無玻璃;`override` 覆寫個別窗 sill/head。
- 空輸入 → `buildSceneModel` 回空模型,不崩潰(理論上被後端 `NoStructureError` 先擋)。
