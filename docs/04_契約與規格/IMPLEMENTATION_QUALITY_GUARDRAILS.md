# RoomPilot 實作品質防呆規範

> 建立日期：2026-07-10
>
> 目的：避免需求只完成部分、畫面看似完成但互動不可用，或把設計參考圖誤當成網頁內容直接嵌入。

## 一、這次只完成部分的原因

### 1. 把「參考圖」誤當成「頁面素材」

使用者提供的圖3是完整的產品介面與流程參考，正確做法是拆解成 HTML、CSS 與 JavaScript 元件；先前卻把完整截圖放進操作區，造成巢狀頁面、內容裁切、視覺重複，也讓使用者誤以為截圖本身可以操作。

### 2. 只完成視覺近似，沒有完成互動驗收

上傳區雖然有 label 與隱藏的 file input，但沒有優先提供清楚可見的「從裝置上傳」按鈕，也沒有用瀏覽器實際驗證點擊、拖曳、檔案預覽與下一步啟用，因此出現「看得到框，但不能用」的問題。

### 3. 沒有把需求拆成可驗收的完成定義

需求同時包含主視覺、步驟列、上傳、即時預覽、逐題聊天與最後 3D。若只檢查畫面是否出現，會漏掉檔案選擇器、狀態切換與頁面流程。之後每個階段都必須先定義畫面、互動、資料與驗收方式，再宣稱完成。

### 4. 沒有在修改後以使用者路徑驗證

單純通過 JavaScript 語法檢查與後端測試，不能代表前端可用。必須從 `/scene` 開始，實際完成「開啟頁面 → 點擊上傳 → 選檔 → 預覽 → 下一步 → 回答問題」的操作測試。

## 二、以後的實作規則

### 設計參考圖規則

- 參考圖只能用來拆解版面、色彩、間距、文字層級與互動流程。
- 不得把完整 UI 截圖嵌入正式操作區，除非需求明確要求展示圖片。
- 若需要使用參考圖中的照片或 3D 主視覺，必須裁切成獨立素材，並確認不包含原本的導覽列、按鈕與表單。
- 每個視覺元件都必須對應到真正的 HTML 元件或資料狀態。

### 功能完成定義

每一個功能必須同時完成以下四項，缺一不可：

1. **畫面**：外觀與參考圖的區塊層級、文字、色彩與狀態一致。
2. **互動**：使用者能點擊、輸入、拖曳或按下一步完成操作。
3. **資料**：操作結果會更新前端狀態，必要時正確送到後端 API。
4. **驗收**：用瀏覽器走完實際使用路徑，並保留測試結果。

## 三、交付前固定檢查順序

1. 先確認畫面是否依照參考圖拆解完成，而非嵌入截圖。
2. 再確認所有主要按鈕都有明確的 `id`、可見文字與事件處理器。
3. 用瀏覽器實際點擊與選檔，不只執行語法檢查。
4. 驗證每個狀態：初始、上傳中、成功、失敗、下一步可用、下一步不可用。
5. 執行前後端測試，並記錄結果。
6. 最後才回報「完成」，並明確列出尚未完成項目。

## 四、這次問題的修正方向

- 將圖3拆成真正的主視覺、步驟列、上傳卡、預覽卡與提醒卡。
- 移除會造成巢狀與裁切的完整參考截圖嵌入方式。
- 為上傳功能加入明確可見的裝置上傳按鈕。
- 加入點擊、拖曳、即時預覽與按鈕狀態更新的瀏覽器驗收。
- 後續聊天頁沿用同一套元件與色彩規則，並以逐題流程驗收。
