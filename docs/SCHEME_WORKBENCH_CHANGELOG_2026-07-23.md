# 材質偏好與三方案工作台改動紀錄

日期：2026-07-23
來源：Step 6／7 整合工作
狀態：未 commit

## 移除或取代

| 原流程／功能 | 原因 | 取代方式 |
|---|---|---|
| 問卷完成後立刻產生單一 2D 家具配置 | 使用者還沒確認風格、牆面與地板素材；單一配置也無法比較設計策略 | 問卷完成後留在 Step 6 最後確認材質偏好，再產生三案 |
| 把素材偏好混在逐房的三題極端選擇裡 | 房間專屬問題必須固定為三題；素材選擇應同時看到全屋預設與逐房覆寫 | 將素材移至 Step 6 最後區段，不新增 6.5 頁籤，並保留原 JSON 欄位兼容既有資料 |
| Step 7 只有一份 `furniture` 陣列 | 微調後無法回到其他方案比較 | 改用 `layout_2d.schemeSet` 保存三份獨立家具陣列與 `activeSchemeId` |
| Step 7 只能看 2D | 無法在採用前檢查立體關係 | 加入同一方案的 2D／3D 切換預覽 |

## 新增

- `design_preferences` 流程關卡與持久化資料。
- 六種第一版整體風格方向。
- 全屋牆面／地板材質、顏色與逐房材質覆寫。
- 三個 fallback 方案：保留優先、需求平衡、機能加強。
- 每案的產生來源與接線狀態：
  - `generation.source`
  - `ragStatus`
  - `agentStatus`
  - `placementEngine`
- Step 7 的方案切換、2D／3D 切換、GLB 搜尋／替換及牆地材質修改。
- `scene_design_workbench.js`：可獨立測試的資料契約與方案版本操作。
- 各方案分別保存家具與牆地材質；切換方案時一併恢復，避免跨方案污染。
- 指定 GLB 後以 catalog ID 載入該筆模型，不再重新猜選同類型家具。
- 跨家具類型替換會同步更新引擎類型與 2D 俯視圖示；沒有支援圖示／類型的模型會明確阻擋。
- 3D 預覽精確帶入目前方案的牆面、地板 surface ID 與顏色。
- 3D 非同步預覽加入版本檢查；快速切換時會丟棄過期回應。
- RAG／Agent 接線狀態可區分 `pending`、`partial`、`connected`。

## 尚待接上

- RAG：依 `clientBrief` 與 `design_preferences` 檢索家具、牆面、地板素材。
- Agent：以 RAG 候選建立真正具有設計差異的三案與理由。
- 家具引擎更新：跨房間重新歸屬、完整貼牆操作與更細緻的重試策略。

尚待項目在 UI 與 JSON 都標為 `pending`，不可宣稱已完成。
