> 整理日期：2026-08-02，依 `feat/furniture-agent-select` 分支實碼盤點（非推測）。
> 本文寫**數學與演算法**：座標約定、公式、判定順序、常數來源。
> 流程／API／檔案職責見 [擺位Agent執行流程.md](擺位Agent執行流程.md)，本文不重複。

**這份文件的用途**：讓沒看過本 repo 的人，只讀本文就能在任何語言重新實作一套
行為等價的擺位引擎，並用 §12 的手算範例逐步核對自己的實作。

核心紀律：**LLM 只決定「選哪些件」，所有座標由確定性演算法算出。**
全流程無隨機、無浮點時間依賴 —— 同輸入必得同輸出（複現條件見 §11）。

## 1. 輸入與管線總覽

### 1.1 輸入資料（plan dict，單位 mm）

| 欄位 | 型別 | 用途 |
| :--- | :--- | :--- |
| `bbox` | `[min_x, min_y, max_x, max_y]` | 決定網格範圍與格徑 |
| `walls` | `[(x1,y1,x2,y2), …]` | 牆中心線，柵格化描粗 |
| `wall_polygons` | `[[(x,y), …], …]` | 牆板環，掃描線填充 |
| `doors` | `[(x1,y1,x2,y2), …]` | 柵格化封洞 + 門前淨空帶 |
| `windows` | `[(x1,y1,x2,y2), …]` | 柵格化封洞 + 窗前採光帶 |

外加：房間清單（`polygon_mm` 邊界環 + `centroid_mm` 質心 + `label`）、
每房選件清單（`kind` + `footprint`(cm) + `height`(cm) + `count`）。

### 1.2 管線

```
plan ──► ① 佔用網格 build_occupancy         （§3）
     ──► ② 通行段   passage_segments        （§4.2）
逐房 ──► ③ 禁放遮罩 blocked_masks(low, band)（§4）
     ──► ④ 房間輪廓邊 _room_edges           （§5.1）
     ──► ⑤ 房型規則  RULES[label]           （§7）
     ──► ⑥ 淨空覆核  _resolve_clearance      （§9.3）
     ──► ⑦ 剩件分流  副件相對主件 / 泛用靠牆 （§8）
     ──► placements（mm）
之後 ──► ⑧ 微調      move / rotate          （§10）
```

## 2. 座標系與角度約定（最易錯的一節）

- 世界座標右手系，**y 軸向上**，單位 **mm**（前端顯示才換 cm，`MM_PER_CM = 10`）。
- 家具 footprint 記為 `(w, d)`：**w = 沿牆方向的寬，d = 離牆的進深**。
- 姿態只用一個純量 `rotation_deg`（記作 θ），語意 = three.js 的 Y 旋轉角。

### 2.1 三個互為逆運算的向量

設 θ 為 `rotation_deg`，r = radians(θ)：

| 名稱 | 公式 | 意義 |
| :--- | :--- | :--- |
| `facing_deg(n)` | θ = degrees(atan2(nₓ, −n_y)) | 「要正面朝向單位向量 n」所需的 θ |
| `front_vector(θ)` | **f = (sin r, −cos r)** | 該 θ 下家具正面的世界方向 |
| 側向 | **s = (−f_y, f_x) = (cos r, sin r)** | 家具本地 **+w**（右）方向 |

`facing_deg` 與 `front_vector` 嚴格互逆：`front_vector(facing_deg(n)) = n`。

### 2.2 ⚠️ 正面 = OBB 本地 −y

`obb_corners` 的本地軸對應世界方向為：

```
本地 +x（半寬 w/2 方向） → ( cos r,  sin r) = s
本地 +y（半深 d/2 方向） → (−sin r,  cos r) = −f
```

也就是 **正面 f 是 OBB 的本地 −y**。`clearance.py` 的註解把「本地深方向 +1」
稱作正面，那是它自己 `_SIDE_DIRS` 的語彙（以 f 為基底），與 `obb_corners`
的 +y 符號相反。本體 OBB 對 ±d 對稱，故此差異**不影響碰撞**，
只在淨空區往哪一側外推時有意義。

> **重寫時一律以 f =（sin r, −cos r）為正面基準**，不要沿用 `obb_corners` 的 +y。

### 2.3 房間輪廓邊的室內法線

房間 polygon 由 flood-fill 輪廓追出，**室內恆在邊的左側**（`segment.py`
「收集房格與非房格之間的有向格邊（室內恆在左）」）。因此：

```
inward(e) = ( −(e.by − e.ay)/L ,  (e.bx − e.ax)/L )     L = |e|
```

即單純的**左法線，不需要質心可見性判斷** —— L 形房、凹房都正確。
（`geometry.inward_normal()` 是另一支「朝質心翻轉」的版本，供不保證繞序的
牆證據邊使用；房間輪廓邊請用左法線版 `rules._edge_inward`。）

## 3. 佔用網格（柵格化）

擺位不做解析幾何，**一切碰撞都在布林網格上判定**。這是全案唯一的碰撞事實源。

### 3.1 網格參數

```
span   = max(bbox_w, bbox_h, 1)
cell   = max(50, span / 1200)                 # 50mm 起跳；奇異尺度檔放大格徑不爆網格
origin = (min_x − 2·cell, min_y − 2·cell)     # 外圍留 2 格白，保證外部連通
nx     = ceil(bbox_w / cell) + 5              # 2·margin + 1
ny     = ceil(bbox_h / cell) + 5
world(ix, iy) = (origin_x + (ix+0.5)·cell, origin_y + (iy+0.5)·cell)
```

`occ[iy, ix]`（**列優先，y 在前**）。True = 結構占據。

### 3.2 畫入規則

```
stroke_r = max(120/2, 0.51·cell)   # 牆厚 120mm 的一半；至少過半格，粗格徑下不漏
edge_r   = 0.51·cell               # 牆板邊線只需「存在」，厚度由填充表達

for ring in wall_polygons:  fill_ring(ring);  每條環邊 stroke(edge_r)
for seg in walls+doors+windows:  stroke(seg, stroke_r)
```

**門窗都要封**：門洞不封則相鄰房間互通、窗洞不封則室內漏到室外，flood-fill 會把
房間誤判成外部。

**掃描線填充**（`_fill_ring`）：對每列取格心 y_c，與環邊求交，採**半開區間規則**
`(y1 ≤ y_c < y2) or (y2 ≤ y_c < y1)`（保證每列與每條跨越邊恰交一次），交點排序後
成對填充，填的是**格心落在 [xa, xb] 內**的格：

```
ix0 = ceil ((xa − ox)/cell − 0.5)
ix1 = floor((xb − ox)/cell − 0.5)
```

**線段描粗**（`_stroke_segment`）：格心到線段的歐氏距離 ≤ r 即占據。

```
t     = clamp(((p − a)·(b − a)) / |b − a|², 0, 1)
dist² = |p − (a + t·(b − a))|²
占據 ⟺ dist² ≤ r²
```

`|b−a|² = 0`（退化點）時取 t = 0。

## 4. 禁放遮罩（True = 禁放）

逐房計算，兩層：

```
blocked_low  = occ | ¬room_mask | stroke(doors, 750) | stroke(passages, 750)
blocked_band = blocked_low | stroke(windows, 400)
```

選用規則（`_blocked_for`）：

```
家具 height_mm ≥ 900（窗台高） → 用 blocked_band（會擋光，必須讓開窗前）
否則                          → 用 blocked_low （矮件貼窗合法）
```

- `room_mask` = 房間 polygon 用同一套掃描線填充畫在獨立畫布上（**不動 `grid.occ`**）。
  `¬room_mask` 讓「房間外」一律禁放 —— 這也是家具不會被移出自己房間的根本原因。
- 淨空帶用 `_stroke_segment` **雙側描粗**，不判法線方向：門／窗的另一側必在房間外，
  已被 `¬room_mask` 蓋掉，因此結構上不可能把淨空帶畫錯側。
- 門窗**不過濾是否鄰接本房**：非鄰接段的淨空帶與本房交集為空，多畫無害。

### 4.2 通行段 passage_segments（牆縫式開口）

沒有 door 實體、只靠牆縫連通的開口，也要留通行淨空：

```
k       = ceil(DOOR_GAP_MM / 2 / cell)      # DOOR_GAP_MM = 1000
closed  = 形態學閉運算(occ, k)               # 8-鄰域 dilate k 次 → erode k 次，封 ≤ 2k 格的縫
closed[外圍 2 格環] ← occ                    # 還原 margin，膨脹灌滿的外環不算縫
gap      = closed & ¬occ                     # 被閉運算補上的格 = 被封的門洞裸縫
interior = label_regions(closed) > 0         # 只留貼室內的塊（外角雜格不貼室內）
```

每個 4-連通縫塊取 bbox，**沿較短半邊方向**過塊心吐一條中線段（穿過縫口）：

```
half_x ≤ half_y → (cx−half_x, cy, cx+half_x, cy)
否則            → (cx, cy−half_y, cx, cy+half_y)
```

寬開口（閉運算封不住）不產格 → 不吐假段。與門帶重疊時冗餘但無害（同進深、同語意）。

## 5. OBB 與碰撞判定

### 5.1 OBB 定義

`Obb(cx, cy, w, d, rad)`，角點：

```
corner(x_l, y_l) = (cx + x_l·cos r − y_l·sin r,  cy + x_l·sin r + y_l·cos r)
                   for (x_l, y_l) ∈ {(−w/2,−d/2), (w/2,−d/2), (w/2,d/2), (−w/2,d/2)}
```

房間輪廓邊由 `_room_edges` 從 `polygon_mm` 依序取（首尾相接，零長邊剔除）。

### 5.2 `obb_blocked(mask, grid, obb)` — 唯一的碰撞函式

```
1. 取 OBB 四角的 AABB → 格索引視窗
      ix0 = int((min_x − ox)/cell),  ix1 = int((max_x − ox)/cell) + 1
      iy0 = int((min_y − oy)/cell),  iy1 = int((max_y − oy)/cell) + 1
2. 越界（ix0<0 or iy0<0 or ix1≥nx or iy1≥ny）→ 回 True（出界 = 房間外 = 必然禁放）
3. 視窗內每個格心 p 反旋轉進 OBB 本地座標：
      l = R(−r)·(p − c)
      inside ⟺ |lₓ| ≤ w/2 且 |l_y| ≤ d/2
4. 回 (inside & mask[視窗]).any()
```

`stamp_obb(mask, …)` 同樣算 inside，改成 `mask |= inside`（越界部分忽略，不報錯）。

**兩件家具是否重疊**也走同一權威（`obb_overlaps`）：把 target 烙進一張暫存畫布，
再拿 probe 測 `obb_blocked`。因此**重疊判定的解析度 = 格徑（預設 50mm）**，
不是解析幾何。呼叫端必須先確認 probe 在網格內，否則出界的 True 會被誤讀成重疊。

### 5.3 合法性三層

```
_free(ctx, tpl, obb) ⟺ ¬obb_blocked(_blocked_for(tpl), obb)  ∧  ¬obb_blocked(ctx.placed, obb)
```

`ctx.placed` 是本房**已放家具的累計烙印**，每放一件就 `stamp_obb` 疊上去，
使同房後續件互不重疊。例外：`rug` 是平面件，**登記但不烙印**（允許家具壓在上面）。

移除或改位家具後必須 `_restamp`（清空重畫全清單），否則被移除的件仍占著位子。

## 6. 靠牆錨定掃描（所有靠牆件的共同骨架）

```
候選邊 = { e ∈ 房間輪廓邊 : |e| ≥ w }
        依 (−|e|, mid_y, mid_x) 排序        # 長邊優先；完整 tie-break 保證決定性
        取前 ANCHOR_EDGE_TRIES = 10 條

for e in 候選邊:
    n   = inward(e)                          # §2.3 左法線
    θ   = facing_deg(n)                      # 正面朝室內
    off = d/2 + WALL_GAP_MM                  # 背面離牆 50mm
    for t in anchor_ts(|e|, w):
        p = a + (b − a)·t + n·off            # 錨點世界座標
        if _free(p, θ): return (p, θ)        # 第一個過關者即用（貪婪不回溯）
return None                                   # 放不下 → 略過該件（不是錯誤）
```

### 6.1 錨點序列 `anchor_ts(L, w)`

```
lo = (w/2 + 50) / L,   hi = 1 − lo
若 lo ≥ hi（邊短於件）→ 只回五定點，交由遮罩否決
n    = max(1, round((hi − lo)·L / 150))            # ANCHOR_STEP_MM = 150
fill = { lo + (hi − lo)·k/n : k = 0..n }，依 |t − 0.5| 升冪排序（穩定排序，同值取小 t）
回傳 = (0.5, 0.35, 0.65, 0.2, 0.8) ++ [t ∈ fill : 與五定點皆相距 > 1e-9]
```

- **五定點是歷史前綴**：先試它們，既有擺位的選點不變（回歸相容）。
- 定點全被踩掉才進 150mm 步進補掃，**由中心向外**（實測案例：1.9m 牆縫但五定點全滅）。
- 五定點即使落在可行域 `[lo, hi]` 外也照試，遮罩會否決。

### 6.2 靠牆掃描的兩個版本

| 函式 | 位置 | 差異 |
| :--- | :--- | :--- |
| `rules._try_against_wall` | 引擎層 | 只驗本體碰撞，回第一個無碰撞點 |
| `place._try_against_wall_clear` | agent 層 | 錨點序列同源，**逐點多驗開合淨空**（§9） |

不能沿用引擎版再補驗 —— 它只回第一個點，淨空不過就沒有下一個候選可要。
無開合需求的 kind，兩版行為完全一致（淨空檢查恆過）。

## 7. 房型規則的座標公式

主件（living→sofa、bedroom→bed、dining→dining_table）在選件中才走房型規則；
主件放不下 → 該規則回空 tuple，剩件仍走 §8 分流。

### 7.1 living

```
sofa: 靠牆錨定 → 得 (p, n, θ)                    # n = inward
ahead(dist) = p + n·dist                          # 沙發正前方 dist 處

rug:   c = ahead(sofa.d/2 + rug.d/2 − 400)        # RUG_TUCK_MM：內收進沙發下 400mm
       合法性只驗遮罩，不驗已放家具（壓沙發是設計）；登記但不烙印
table: c = ahead(sofa.d/2 + 450 + table.d/2)      # TABLE_GAP_MM：沙發前緣到茶几 450mm 走距
tv:    見下
```

**電視櫃**：沙發正前方**最遠的平行牆**。

```
平行判定：diff = |edge_angle(e) − r_sofa| mod π ,  min(diff, π − diff) ≤ radians(30)
前方判定：proj(e) = (mid(e) − p_sofa)·n_sofa > 0
候選集 = { e : |e| ≥ tv.w ∧ 平行 ∧ 在前方 }，依 (−proj, mid_y, mid_x) 排序
對每條候選邊跑 §6 的錨點掃描，第一個過關即用
```

> 為何 `mod π` 可直接比？設牆方向角 φ，左法線 n =(−sin φ, cos φ)，
> 則 θ = facing_deg(n) = φ + π。兩邊都差同一個 π，mod π 後恰好抵銷，
> 等價於比較兩牆的走向。

### 7.2 bedroom

```
bed: 靠牆錨定 → (p, n, θ)
     床頭板通常高過窗台（≥900）→ 自動吃 blocked_band → 天然不貼窗
```

**床頭櫃**（至多 `ns_max = min(2, count)` 件）：

```
u    = (n_y, −n_x)                                # 沿牆方向（inward 順轉 90°）
back = bed.d/2 − ns.d/2                           # 背線與床頭板齊
side = bed.w/2 + ns.w/2 + 50                      # SIDE_GAP_MM，床側向間距
cap  = bed.d − ns.d                               # 滑到底仍不越床尾

for sign in (+1, −1):                             # 床的兩側
    for fwd in (0, 150, 300):                     # 床頭角被占 → 沿床側向床尾滑位
        if fwd > cap: break
        c = p − n·(back − fwd) + u·side·sign
        if _free(c, θ): 放置; break               # 該側成功就換下一側
    if 已放 ≥ ns_max: break
```

`wardrobe`：另跑一次獨立的靠牆錨定（§6）。

### 7.3 dining

```
longest  = 最長的房間輪廓邊
base_deg = facing_deg(inward(longest))            # 對齊最長牆走向
c        = room.centroid_mm                       # 餐桌置房間質心

for θ in (base_deg, base_deg + 90):               # 不行就轉 90°
    if _free(c, θ): 用這個 θ; break
else: return ()                                    # 餐桌放不下 → 整條規則回空
```

**餐椅**（兩長邊各 2 張，面向餐桌）：

```
r = radians(θ_table)
w_dir = ( cos r, sin r)                            # 桌寬方向
d_dir = (−sin r, cos r)                            # 桌深方向
depth_off = table.d/2 + chair.d/2 + 30             # CHAIR_GAP_MM

for side in (+1, −1):
    face  = −d_dir·side                            # 椅子面向餐桌
    θ_ch  = facing_deg(face)
    for along in (−table.w/4, +table.w/4):
        c = c_table + d_dir·depth_off·side + w_dir·along
        if _free(c, θ_ch): 放置
```

## 8. 剩件分流（規則沒吃掉的件）

排序：**非副件先擺**（`sorted(key = kind ∈ COMPANION_OF)`，穩定排序）——
副件的主件可能還在剩件裡（辦公椅在等它的書桌）。

### 8.1 副件：只准相對主件擺

`COMPANION_OF`（副件 → 可接受主件，依序取第一個已就位者）：

| 副件 | 主件 |
| :--- | :--- |
| `nightstand` | `bed` |
| `coffee_table` | `sofa` |
| `tv` | `sofa` |
| `dining_chair` | `dining_table` |
| `office_chair` | `office_desk`, `desk` |

**主件正前方、面向主件**（`_try_facing_anchor`）：

```
f   = front_vector(θ_anchor)
off = anchor.d/2 + tpl.d/2 + 30                    # CHAIR_GAP_MM
c   = p_anchor + f·off
θ   = facing_deg(−f)                                # 回頭面向主件（= θ_anchor + 180°）
過關條件：_free(c, θ) ∧ clearance_free(c, θ)
```

三種情形一律**略過並記 log，寧缺勿亂**（絕不退回泛用靠牆）：

1. 本房主件未就位；
2. 該 kind 已被房型規則試過（`RULE_KINDS_BY_LABEL`）—— 規則失敗表示相對位不可行，重試只會得到錯位置；
3. 相對位本體或淨空不可行。

> 這是「床頭櫃不該流落到離床很遠的牆邊」的根治點。
> 副件恆擺 **1 件**（count 不展開）：現行唯一策略是「主件正前」，一個主件前只有一個位。

### 8.2 泛用件：逐件靠牆

衣櫃／書櫃／矮櫃…：跑 `_try_against_wall_clear`（§6.2，含淨空）**×count**，
**放不下即止**（不繼續試後面的件）。主件放不下時，自足泛用件仍獨立擺出 ——
整房清空對使用者更差。

## 9. 開合淨空（門扇／抽屜的操作空間）

### 9.1 需求表（`knowledge.CLEARANCE_OF`，宣告式資料，缺項 = 無需求）

| kind | 面 | 進深 (mm) | 理由 |
| :--- | :--- | ---: | :--- |
| `wardrobe` | front | 600 | 對開門扇全開 |
| `cabinet_low` | front | 450 | 抽屜拉出 |
| `dressing_table` | front | 450 | 抽屜拉出 + 坐入 |
| `nightstand` | front | 350 | 小抽屜拉出 |

沙發、茶几、床、開放式書櫃…無開合需求，完全跳過淨空檢查。

### 9.2 淨空區幾何 `zone_obb`

淨空區 = 家具指定面外緣往外延伸 `depth` 的 OBB，**與家具同角度**（跟著旋轉）：

```
f = front_vector(θ)          s = (−f_y, f_x)

front:  c_zone = c + f·(d/2 + depth/2),   zone = Obb(w = w,     d = depth, rad = r)
back:   c_zone = c − f·(d/2 + depth/2),   zone = Obb(w = w,     d = depth, rad = r)
right:  c_zone = c + s·(w/2 + depth/2),   zone = Obb(w = depth, d = d,     rad = r)
left:   c_zone = c − s·(w/2 + depth/2),   zone = Obb(w = depth, d = d,     rad = r)
```

front／back 的淨空**與家具同寬**；left／right **與家具同深**。

### 9.3 衝突判定順序（`clearance_conflict`，回 None 表示過關）

失敗訊息是**繁中、可直接轉述給使用者**的原句（沿用原引擎詞彙）：

| # | 條件 | 訊息 |
| --: | :--- | :--- |
| 1 | 自己的淨空撞 `blocked_low` | 「X」的開合空間被牆體或動線阻擋 |
| 2 | 自己的淨空撞他件本體 | 「X」的開合空間與「Y」衝突 |
| 3 | 自己的淨空撞他件淨空 | 「X」與「Y」的開合空間互相衝突 |
| 4 | *(reverse)* 自己本體壓到他件淨空 | 擋住了「Y」的開合空間 |

- 第 1 項驗的是 **`low`，不是 `band`** —— 淨空是「人站立操作」的空間，落在窗前合法。
- `reverse=False` 供「逐件覆核既有配置」使用：第 4 項會在對方那一輪以第 2 項的
  身分被抓到，兩邊都報只是重複噪音。
- 擺位掃描用布林版 `clearance_free`（= `clearance_conflict(...) is None`）逐點快篩。

### 9.4 兩個強制點

| 位置 | 行為 |
| :--- | :--- |
| `_place_generic` / `_place_companion` | 候選點**逐點先驗**，不過就換下一個錨點／略過 |
| `_resolve_clearance`（房型規則產物覆核） | 見下表 |

房型規則層（`app/furniture/rules.py`）**不認得淨空** —— 它在 `app.*`，
依賴方向上不能 import agent 的知識庫，因此由 agent 層收尾覆核（`reverse=False`）：

| 違規件類型 | 處置 | 理由 |
| :--- | :--- | :--- |
| 主件（sofa/bed/dining_table） | **保留**，只記 log | 整房沒了主件對使用者更差 |
| 副件（`COMPANION_OF`） | **移除** | 相對主件是它唯一合法位，寧缺勿亂 |
| 其餘泛用件 | **移除後退回剩件分流** | 由淨空版靠牆掃描（§6.2）重擺 |

每次移除都要 `_restamp` 重建 `ctx.placed`。

> 副作用：極小房（如 1.6m 見方）放了衣櫃後，600mm 門扇淨空可能吃掉其餘牆位，
> 其他泛用件會被略過而非硬塞。這是預期行為。

## 10. 微調（move / rotate）

只吃**拆解好的結構化指令**（自然語言理解不在此層）：

```json
{"action": "move",   "target": "r1-bed-0", "dx": 500, "dy": 0}
{"action": "rotate", "target": "r1-bed-0", "rotation": 90}
```

### 10.1 候選姿態的合法性（`_conflict`，三層依序）

```
1. obb_blocked(_blocked_for(cand), body)  → 「X」超出可放範圍（房外/牆體/門前動線）
2. 對每個他件 obb_overlaps(body, other)   → 與「Y」重疊
3. placement_conflict(cand, others)       → §9.3 四項（reverse=True）
```

**注意：微調不使用 `ctx.placed`** —— 那份累計遮罩含目標自己的烙印，拿來判重疊會
與自己相撞。他件碰撞改由 placements 清單逐件比對。

`_blocked_for` 在此以 `Placement.height_mm ≥ 900` 判定；模板流／chat 加件不帶高度
（預設 0.0）→ 走純動線遮罩 `low`。

### 10.2 move：軸分離

```
若 dx = dy = 0 → 成功（沒要求移動，不是失敗）
moved = false
若 dx ≠ 0：試 (x+dx, y)          → 過關則採用，moved = true
若 dy ≠ 0：試 (x_current, y+dy)  → 過關則採用，moved = true   # 吃 X 軸的結果
若 ¬moved：失敗，reason = _conflict(雙軸同時位移的目標點)      # 最貼近使用者本意
```

**能走多少走多少**：單軸被擋仍算成功（該軸座標不變），雙軸都被擋才失敗。
`delta = 0` 的軸**不計入成功** —— 否則「只想往 Y 移但被擋死」會回報假成功。

### 10.3 rotate

角度正規化 `rotation % 360`；不合法就**保持原角度**並回失敗原因。

### 10.4 不可變

絕不就地改 `Placement`：一律 `dataclasses.replace` 產新物件，
失敗時回傳的是**未變動的原清單**（呼叫端可直接沿用）。

### 10.5 前端拖曳的角色分工

2D 拖曳只是**預覽**：`snap.ts` 把中心吸到就近牆面（`|gap| < 8cm`）或 10cm 格線，
旋轉把手吸到 45° 倍數（±6°）；**前端完全不判合法性**。放手時
`adjustFromDrag(前, 後)` 算出差量（低於 0.01cm / 0.01° 視為沒動 → 回 null，不打後端），
送**「拖曳前」的 placements + 差量**給後端定案。

> 送拖曳前姿態 + 差量，而非拖曳後的預覽姿態 —— 否則等於拿還沒驗過的位置當起點再驗一次。

## 12. 決定性與複現條件

無隨機數、無時間依賴、無並行；同輸入必得同輸出。要複現需要對齊的是：

1. **排序 tie-break 必須完整**：邊排序鍵 `(−len, mid_y, mid_x)`、
   電視候選 `(−proj, mid_y, mid_x)`，第二三鍵不可省。
2. **穩定排序**：`anchor_ts` 的 fill 依 `|t−0.5|` 排序時，同值取較小 t；
   剩件的 `sorted(key = kind ∈ COMPANION_OF)` 依賴穩定性維持原順序。
3. **選件順序即擺放順序**：`by_kind` 由 selections 的 items 順序建成（dict 保序），
   同一組件不同送出順序**會**得到不同結果。要逐位元複現就要固定 selections 順序。
4. **貪婪不回溯**：任何一件放下就不再更動；先放的件會擠掉後放的件。
   （原始碼標 `# ponytail:` —— 放置率不足時才上 backtracking。）
5. **格徑影響結果**：碰撞解析度 = `cell`。改 `DEFAULT_CELL_MM` 或觸發
   `MAX_CELLS_PER_AXIS` 放大，邊界案例的成敗會變。
6. 浮點：全用 float64，無容差比較除了 `anchor_ts` 的 `1e-9` 去重與
   `adjustCommand` 的 0.01 門檻。

## 13. 手算驗證範例

用來核對重新實作的第一組數字。

**輸入**：矩形房 `(0,0) (4000,0) (4000,3000) (0,3000)`（CCW，室內在左），
床 `w=1500, d=2000, height=1200`，床頭櫃 `w=450, d=400`，無門窗遮擋中央區。

**① 邊排序**（`(−len, mid_y, mid_x)`）

| 邊 | 端點 | len | mid | 排序鍵 | 名次 |
| :--- | :--- | ---: | :--- | :--- | ---: |
| e0 | (0,0)→(4000,0) | 4000 | (2000, 0) | (−4000, 0, 2000) | 1 |
| e2 | (4000,3000)→(0,3000) | 4000 | (2000, 3000) | (−4000, 3000, 2000) | 2 |
| e3 | (0,3000)→(0,0) | 3000 | (0, 1500) | (−3000, 1500, 0) | 3 |
| e1 | (4000,0)→(4000,3000) | 3000 | (4000, 1500) | (−3000, 1500, 4000) | 4 |

**② e0 的室內法線與朝向**

```
inward = (−(0−0)/4000, (4000−0)/4000) = (0, 1)        ✔ 指向房內
θ      = degrees(atan2(0, −1)) = 180°
驗算：front_vector(180°) = (sin180°, −cos180°) = (0, 1) = inward   ✔ 互逆
```

**③ 錨點序列** `anchor_ts(L=4000, w=1500)`

```
lo = (750 + 50)/4000 = 0.2      hi = 0.8
n  = max(1, round(0.6 × 4000 / 150)) = 16
fill 步距 = 0.6/16 = 0.0375 → {0.2, 0.2375, …, 0.8}
去掉與五定點重合者（0.2, 0.35, 0.5, 0.65, 0.8）後，依 |t−0.5| 接在五定點之後
最終序列開頭 = (0.5, 0.35, 0.65, 0.2, 0.8, 0.4625, 0.5375, 0.425, 0.575, …)
```

**④ 床的落點**（t = 0.5 過關）

```
off = d/2 + WALL_GAP = 2000/2 + 50 = 1050
p   = (0,0) + (4000,0)×0.5 + (0,1)×1050 = (2000, 1050)
床：center (2000, 1050), rotation 180°
驗算：背面在 y = 1050 − 1000 = 50 → 離牆 50mm ✔
```

**⑤ 床頭櫃**

```
u    = (n_y, −n_x) = (1, 0)
back = 2000/2 − 400/2 = 800
side = 1500/2 + 450/2 + 50 = 1025
fwd  = 0（首選）
c(+) = (2000,1050) − (0,1)×800 + (1,0)×1025 = (3025, 250)
c(−) = (2000,1050) − (0,1)×800 − (1,0)×1025 = ( 975, 250)
驗算：背面 y = 250 − 200 = 50，與床背線齊 ✔；側向間隙 = 3025 − 225 − (2000+750) = 50 ✔
```

**⑥ 床頭櫃的淨空區**（`nightstand: front 350`）

```
f      = front_vector(180°) = (0, 1)
off    = d/2 + depth/2 = 200 + 175 = 375
c_zone = (3025, 250 + 375) = (3025, 625)
zone   = Obb(cx=3025, cy=625, w=450, d=350, rad=π)
```

該區必須不撞 `blocked_low`、不撞床本體、不撞另一個床頭櫃的淨空。

## 14. 已知近似與限制

原始碼以 `# ponytail:` 標記「先用近似、需求出現再升級」之處：

| 近似 | 位置 | 升級條件 |
| :--- | :--- | :--- |
| 貪婪不回溯 | rules.py | 放置率不足 → 局部搜尋 / backtracking |
| 窗前採光用固定進深 400mm | constraints.py | 需要真實日照角 → 射線模擬 |
| 窗台高 900mm 為全域校準值 | constraints.py | 逐窗高度差異出現 → per-window |
| 通行縫方向取 bbox 短邊 | segment.py | 斜牆縫出現 → PCA 主軸 |
| 縫寬閉運算會順帶吃掉極窄走道 | segment.py | → 沿牆方向性閉運算 |
| 房間輪廓不表達洞（內部島） | segment.py | 疊圖／標籤用不到 |
| 前端角落雙吸為序貫貼齊 | snap.ts | 斜牆 → 兩面法向 2×2 聯立一次定位 |
| `obb_overlaps` 每次配一張全網格暫存 | clearance.py | 件數上升成效能瓶頸時改局部視窗 |

其他既定限制：

- **家具不會被移出自己的房間**（遮罩逐房算，`¬room_mask` 直接禁放房外）。跨房搬移需換 room 重算。
- 微調只支援 `move` / `rotate`；`add` / `remove` 與相對方位指令（toward_window 等）未實作。
- 副件恆擺 1 件；多件需求需擴充「沿主件邊多位嘗試」。
- 重疊判定解析度 = 格徑，兩件相距 < 50mm 可能被判為不重疊。
