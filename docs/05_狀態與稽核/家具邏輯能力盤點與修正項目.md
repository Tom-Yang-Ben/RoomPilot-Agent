# 家具邏輯能力盤點與修正項目

> 盤點日期:2026-07-07 ・ 規則分層補充:2026-07-08
> 範圍:`roompilot/engine/`(placement / adjustment / clearance / geometry)+ `roompilot/catalog/`(型錄語意)+ `roompilot/server/scene_service.py`(自動配置)
> 定位:記錄「目前做到哪」與「接下來該修正/補強什麼」,供 F3 Agent 開發與 Demo 前排優先序參考。

## 一、目前已做到的能力

### 1. 幾何合法性把關(核心強項)

- Shapely 精確多邊形碰撞:家具本體 vs 房間邊界、牆體、其他家具,支援任意旋轉角度。
- **開合淨空(clearance)**:收納類(書櫃/邊櫃/衣櫃/書桌,見 `style_db.CLEARANCE_BY_TYPE`)可宣告某一面的開門/抽拉深度,淨空區跟著旋轉,三向檢查:

  1. 淨空撞牆(門打不開)
  2. 淨空撞其他家具本體
  3. 兩件家具的淨空互撞

  - 另有反向檢查:新家具本體不得壓到既有家具的開合空間。
- 失敗回傳**繁中具體原因**(如「衣櫃的開合空間被牆體阻擋」),不默默失敗、不硬塞。

> **查證備註(2026-07-08):** 機制上任何家具都能宣告淨空,但型錄實際接上資料的只有上述四類;冰箱/五斗櫃僅存在於早期 docstring,尚無實例。

### 2. 自動配置(rule-based)

- **14 個分支、涵蓋 17 個類型 id** 的擺放常識錨點(`scene_service._placement_candidates`):沙發靠牆、電視櫃貼牆、茶几在沙發前、床頭櫃貼床側、餐椅圍餐桌等;錨點全是相對房間 bbox 的固定位置,**沒有家具配對推理**(「餐椅圍餐桌」是靠慣例佈局湊出來的效果)。錨點放不下退到 3×3 網格候選,再不行走引擎 `place_furniture`。
- 每個候選位置都過引擎碰撞+淨空檢查,放不下回報 `placement.failed`。
- 地毯、壁架不參與碰撞(`_IGNORE_COLLISION_TYPES`)。
- 選品端有風格/色彩/尺度/調和度評分,從 IKEA 型錄挑品項。

> **查證備註:** dataset/ 實際約 1,517 個 GLB(非 1,662);約四成家具尺寸為名稱解析或類型預設修補值,非全數型錄原值。

### 3. 互動微調

- **軸分離移動**:X、Y 分開檢查;單軸內是全有全無(擋下就整軸還原),「沿牆滑」是軸分離的副作用,不是顯式邏輯。
- 旋轉不合法自動還原。
- 自動配置一律回打 `/api/scene/layout`;但 `frontend3d` 拖曳仍完全本地、零驗證(收斂待 F6 決策)。
- `adjust_furniture` 目前沒有任何 server endpoint 在用(僅 examples 與測試);F3 接上 schema tool 後才會成為主線。
- `engine/schema.py` LLM tool schema 已備妥,結構化指令介面就緒。

### 4. 端到端管線

- DXF 平面圖 → 3D 白模 → 自動配置 → 3D 編輯器拖曳微調。
- 單位與座標:2026-07-08 全隊拍板**一律公分(cm)**;引擎內部與 `dxf_room.py` 輸出已公分化;`scene_service.py` / `style_db.py` 遷移由 server/catalog 負責人同步。

## 二、規則分層架構(2026-07-08 拍板)

### 分層原則

**大部分規則應寫在 engine,但不要全部塞進 `placement.py`。**

| 層級 | 職責 | 範例 |
|------|------|------|
| **engine** | 可判斷對錯:碰撞、支撐、動線/門扇/抽屜能否通過 | `geometry.py`、`clearance.py`、`support.py`(新) |
| **catalog** | 規則資料:每件家具是什麼、能放哪、提供什麼支撐面 | `placement_semantics.py`(新) |
| **server** | 候選生成、選品排序、把 engine 警告包進 payload | `_placement_candidates`、`generate_layout` |
| **Agent (F3)** | 依 `client_brief` 調整軟規則權重 | 「採光很重要」→ 加重 daylight 扣分 |

**嚴格度預設(分層):**

- **硬擋:** 碰撞、出界、穿牆、支撐關係錯誤、入口堵死、門扇/抽屜開啟後無法通過
- **軟警告:** 人體工學距離、動線寬度(80/90 cm)、採光遮擋、轉角卡死(可後升硬擋)

**定位不變:** 引擎守住「合法性」,「好不好看、順不順」交給 Agent 層迭代。

### 建議 engine 模組

```
roompilot/engine/
  models.py          # + elevation, parent_id; Room + doors, windows
  geometry.py        # 2.5D 高度區間碰撞
  clearance.py       # 開合淨空(抽屜/門扇) — 已有
  support.py         # 支撐關係 — 硬擋(新)
  door_swing.py      # 門扇掃掠弧 — 硬擋(新)
  circulation.py     # 動線連通/寬度 — 硬+軟(新)
  ergonomics.py      # 人體工學 — 軟警告(新)
  daylight.py        # 採光遮擋 — 軟警告(新)
  scoring.py         # 候選評分(新)
  validation.py      # 統一入口:硬擋 + 警告(新)

roompilot/catalog/
  placement_semantics.py  # 每類型 requires_support / provides_support(新)
```

統一入口示意:

```python
def validate_placement(item, room, placed) -> ValidationResult:
    hard_reason = (
        check_placement_with_clearance(...)
        or check_support(...)
        or check_entrance_blocked(...)
    )
    warnings = (
        ergonomics.check(...)
        + circulation.check_width(...)
        + daylight.check(...)
    )
    return ValidationResult(ok=hard_reason is None, hard_reason=hard_reason, warnings=warnings)
```

### 不該全塞 engine 的項目

| 項目 | 原因 | 放哪 |
|------|------|------|
| 「沙發靠牆面向電視」錨點 | 候選生成策略,非合法性 | `scene_service._placement_candidates` |
| 風格選品 | 型錄/風格 DB | `catalog/` |
| Agent 解讀「採光很重要」 | 權重調整 | F3 + `client_brief.layout_rules` |
| 廚房工作三角 | 需辨識水槽/爐具/冰箱三點,ROI 低 | P3 或 Agent tool |

## 三、四類規則規格(待實作)

### A. 物件放置規則(支撐語意)

**不要**寫成逐條 if-else(`電視必須在電視櫃上`、`筆電不能放地板`…),改用 **Placement Semantics** 放在型錄,catalog 定義、engine 驗證。

```python
@dataclass
class PlacementSemantics:
    placement_class: str      # floor | wall | surface_item | decor | appliance
    requires_support: list[str] | None   # None=地板; ["tv-bench"]; ["desk","dining-table"]
    provides_support: SupportSurface | None
    overlap_policy: str = "normal"       # normal | ignore_body | carpet_pass_through

@dataclass
class SupportSurface:
    elevation_cm: float       # 支撐面離地高度
    max_load_height_cm: float # 可再堆多高
    allowed_on_top: list[str] # 允許放上的 type/tag
```

| 需求 | 語意寫法 |
|------|---------|
| 床放地板 | `placement_class=floor`, `requires_support=None` |
| 筆電不能放地板 | `placement_class=surface_item`, `requires_support=["desk","dining-table","coffee-table"]` |
| 電視放電視櫃上 | `requires_support=["tv-bench"]` + child `elevation = parent.top` |
| 花瓶放桌上 | `placement_class=decor`, `requires_support=["desk","dining-table","side-table","coffee-table"]` |
| 地毯上可再放物品 | `overlap_policy=carpet_pass_through` + `provides_support`(elevation≈0) |
| 壁架 | `placement_class=wall`, `requires_support=["wall"]`(2.5D 後完整) |

- **模組:** `engine/support.py` — `check_support()` — **硬擋**
- **與 clearance 分工:** clearance = 開合動作空間;support = 物品在誰上面
- **前置:** 2.5D(`PlacedFurniture.elevation`、`parent_id`;碰撞改為平面重疊 AND 高度區間相交才算撞)
- **銜接:** `_IGNORE_COLLISION_TYPES` 應逐步改為 catalog 的 `overlap_policy`

### B. 人體工學

- **模組:** `engine/ergonomics.py` — 回傳 `list[Warning]`,**不擋放置**
- **配對距離規則(pairwise):**

| 規則 | 建議值(cm) |
|------|-----------|
| 床兩側走道 | 60–75 |
| 床尾走道 | 80–100 |
| 沙發 ↔ 茶几 | 40–50 |
| 沙發 ↔ 電視櫃(觀看距離) | 250–300 |
| 餐桌拉椅空間 | ≥ 90 |

> 資料模型沒有獨立 `tv` 類型,觀看距離以 `tv-bench` 為錨點。

- **開合運動學(kinematic)** — 歸 clearance / door_swing,**硬擋**:

| 規則 | 歸屬 |
|------|------|
| 抽屜打開後仍可行走 | 擴充 `clearance.py`,把 desk/wardrobe 的 `depth` 設對 |
| 門開啟半徑不能撞家具 | 新 `door_swing.py`,需 `Room.doors` |
| 廚房工作三角 | **P3**,Demo 前不做 |

### C. 空間動線

- **模組:** `engine/circulation.py`(與原 P1-1 / P3-8 **合併**,避免重複實作)

| 要求 | 嚴格度 | 實作 |
|------|--------|------|
| 主要動線 ≥ 80 cm | 軟警告(可後升硬擋) | `free_space = room_poly - union(footprints)` → `buffer(-40)` |
| 無障礙 ≥ 90 cm | 軟警告(client_brief 可升硬擋) | 同上,`buffer(-45)` |
| 轉角不可卡住 | 軟→硬 | free space 轉角處局部寬度檢查 |
| 入口不能被家具堵住 | **硬擋** | 門點到 free space 必須連通 |

- **無門弱版(前置):** 門資料尚未進 engine 前,至少做「自由空間不得被切成不連通碎塊」
- **瓶頸:** `scene_service` 已有 `door_segments`,但 `dxf_room.py` 建 `Room` 時仍丟棄 doors — engine 內需一次補 `Room.doors` / `Room.windows`

### D. 採光

- **模組:** `engine/daylight.py` — **預設軟警告**
- **規則:** 高櫃/大書櫃/冰箱(`height > 閾值` 且 `type in tall_storage`)在窗前方投影帶內 → 警告;可依窗寬、距離分級
- **輸入:** `Room.windows`(窗線段/中心/法向)+ 家具高度與平面位置
- **銜接:** `scene_service` 已有 `keep_window_clear` 問卷,目前只寫進 `layout_rules` 文字,**尚未呼叫 engine**;接上後可升為硬擋或評分重罰
- **近似:** 窗法向 + 窗前方扇形/矩形遮擋帶即可,不必等完整日照模擬

## 五、實作順序建議(engine 主責,約 2 週)

1. **2.5D 基礎** — `elevation` / `parent_id`、高度區間碰撞、`placement_semantics` 資料表
2. **support.py** — 支撐關係硬擋(物件放置規則核心)
3. **circulation 弱版** — 自由空間連通性;入口硬擋待門資料
4. **Room.doors / Room.windows** — `dxf_room.py` 停止丟棄開口資料
5. **door_swing + clearance 補齊** — 門扇掃掠、抽屜行走
6. **ergonomics.py + daylight.py** — 軟警告
7. **scoring.py + validation.py** — 候選評分、統一入口;產 server 交接清單

**速贏可並行:** P3-9 淨空互斥放寬(半天)。

**共同瓶頸:** 門窗資料一次補進 `Room`,不要分三次做。

**payload 影響:** 2.5D 會新增 `elevation`、`parent_id`,需與後端(立凱)/前端對齊。

## 六、定位總結

以 Demo 級室內設計工具而言,家具邏輯已達 **IKEA Home Planner 等消費級工具的核心水準**(真實尺寸、碰撞、開合淨空、常識位擺放),且淨空互斥檢查比多數同級工具嚴謹。

下一階段差距在:**支撐關係(上下堆疊)、動線、人體工學、採光、全局最佳化** — 依本文件分層,硬合法性留在 engine,候選策略在 server,權重迭代交給 F3 Agent。
