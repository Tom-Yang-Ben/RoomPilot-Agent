# RoomPilot 專案流程與 DXF／PNG → 3D 白模

建立可續作的 RoomPilot 專案，再把 DXF 或 PNG 平面圖辨識為 2D 幾何並轉成 3D 場景：**牆壁**（實體擠出）與**窗戶**（玻璃面板），格局比例保留。

- **後端** `roompilot/server/` — FastAPI、SQLite 專案狀態；`ezdxf` 解析 DXF，PNG 經 `roompilot/floorplan/` 辨識後交給同一套升維流程。
- **前端** `frontend3d/` — Vite + React + React Three Fiber (drei) 即時渲染。

## 跑起來

正式操作只有一個網址與一個後端程序：

```bash
# 修改前端後先建置（在 frontend3d/）
npm ci
npm run build

# 後端（回 repo 根目錄跑，相對 import）
uv run --extra vision uvicorn roompilot.server.main:app --port 8002
# 開 http://127.0.0.1:8002/scene
```

建置產物會進入 `roompilot/server/static/frontend3d/`，由 FastAPI 的 `/scene` 直接交付。`npm run dev` 只供開發熱更新，會把 `/api` 代理到 8002，不是使用者需要開啟的第二個產品網站。

## 用法

- **建立新專案**：輸入名稱與選填備註，成功後網址會加入 `project_id` 並進入上傳步驟。
- **續作**：重新開啟含 `project_id` 的網址；伺服器 SQLite 是正式資料，瀏覽器快取只在斷線時備援。
- **選擇平面圖**：下拉選 `testdata/pic/temp/` 既有的 DXF，或上傳 **DXF／PNG**（P0，20 MB 以內）。原檔與辨識結果都會綁定專案；JPG/JPEG/BMP 暫不列入 P0 UI。
- **OpenRouter 建議**：PNG 上傳前可勾選同意；伺服器另須設定 `OPENROUTER_API_KEY`。AI 只補房型、固定機能空間與門窗數第二意見，牆體幾何仍由離線管線產生。DXF 不送 OpenRouter，房名取自 TEXT／MTEXT。
- **沿牆拉線設定比例**：分析後先選定一面辨識牆；第二端點與後續拖曳都被限制在同一面牆上。輸入這段牆的實際公分數後，後端以公分重算全圖。比例未確認前不能送出空間定稿，原始圖片不作校尺底圖。
- **2D 人工定稿**：房間多邊形先由離線牆體拓樸產生，右側可逐房改房型；圖上可補畫、選取與刪除門窗線段。只有按下「我已確認」後的版本會進入 3D，AI 原始建議保留在專案供稽核。
- **針對性需求問卷**：空間確認後先填風格方向與居住人數；一般案件可直接採用房型預設值，需要客製時才展開逐房機能、材質、指定 GLB 家具與自由文字。
- **特殊需求確認**：勾選欄位直接轉 JSON。只有使用者同意時才把進階自由文字送到 OpenRouter；畫面會顯示 AI 或本機規則建議，使用者勾選「已檢查」並確認後才進入後續佈局。
- **AI 自動配置 2D 家具**：需求確認後逐房選件並由 `roompilot.engine` 以公分計算合法座標。OpenRouter 必須另行勾選同意，而且只能從伺服器候選 ID 提建議、不能輸出座標；未同意或服務不可用時走本機房型規則。
- **2D 配置人工定稿**：逐房顯示真實家具 footprint，可拖曳、旋轉或移除搭配建議；每次拖曳／旋轉都由專案 API 驗證房間邊界、家具碰撞、收納淨空與門口淨空。問卷指定型號不可移除，使用者勾選逐房確認後才進入 3D。
- **3D 白模與取景**：白模驗收家具公分尺寸與真實窗洞；確認後可手動調整攝影機，視角以公分座標、觀看目標與 FOV 鎖進專案。
- **18 色卡與家具保護規則**：問卷明確選過的家具型號保持不變；未指定家具依新色卡換成同類型風格候選，且重新走 `roompilot.engine` 驗證位置。
- **最終 PNG**：P0 由目前鎖定場景產生 PNG，按白模／取景／色卡版本保存到 `.runtime/renders/`，可從歷史清單下載。PDF 提案報告列 P1。
- **示範圖除錯長邊**：全圖長邊輸入不屬於上傳主流程，只在內建示範 DXF 模式保留作解析除錯。使用者上傳的平面圖一律在辨識後牆線上，以公分完成兩點校尺。
- **牆厚**：buffer 半徑×2。調大可把分開的雙線牆合併成一道實牆。
- **樓高 / 牆窗門地板顯示**：即時切換。

專案 runtime 預設在 repo 的 `.runtime/`，可用 `ROOMPILOT_RUNTIME_DIR` 指定其他絕對路徑。

## 設計取捨

- 牆 = shapely `buffer`（方形端蓋，角落補成直角）合併線段 ∪ HATCH 填充多邊形（牆常以實心 hatch 畫，缺它牆會破碎）。HATCH 多迴圈用 even-odd（XOR）處理，使「外框−房間」這種環狀牆保持中空。
- **依葉節點圖層分類**：圖塊（INSERT）內的窗線常掛在 window 圖層、但圖塊本身放在別的圖層（如 DIM1）。因此遞迴展開後以「最內層實體自己的圖層」分類，才不會漏掉窗。
- **逐房間切割**：以 bbox 減牆體取得自由空間，再用多組保守閉合半徑補上門洞造成的拓樸缺口；無 WALL 圖層時不做閉合，避免把家具線誤切成房間。每個區域有穩定 ID、面積、標籤來源、信心度與確認狀態。
- 自我檢查：`python backend/dxf_parser.py` 會跑過 7 個檔，斷言每個都解析出牆體與合理比例。
